# 《舆论刹车》美术制作与 AI 资产生成指南

> 版本：v0.1 · 建立日期：2026-10-14
> 用途：保存美术决策、拆分方式、生成步骤与资产状态，供作者逐步用 AI 制作素材，并供后续开发者恢复上下文。
> 当前状态：尚未选定具体画风、尚无通过验收的正式美术资产。本轮只建立文档，不生成图片、音频或视频，不修改游戏代码。
> 本文中的像素尺寸、分层方式、示例文件名与提示词是**制作建议**，不是作者已批准的美术定稿或数值参数。

## 0. 从这里开始：第一轮只做什么

不要一开始生成整套素材。先完成下面三张**参考图**，它们不直接作为游戏运行资产：

1. **风格样张**：同画面出现大头角色、驾驶舱一角、鞋、刹车踏板与按钮示意，检查是否属于同一个视觉体系。
2. **主界面构图**：明确标题留白、开始测试、测试档案的位置；文字和按钮在游戏中由 UI 实现。
3. **驾驶舱完整构图**：明确第一人称视点、窗外、仪表台、空调、座椅控制、腿脚与踏板位置。

三图通过后，先从驾驶舱做一个小型拼装包：**内饰底层＋窗框前景＋窗外层**。导入后检查画面能否对齐、能否适配 PC 和手机，再继续腿脚和踏板。

**第一轮暂不做**：所有服装变体、全部天气、断裂逐帧动画、几十个头像、宣传图、配音、视频。

制作顺序：

```text
确认风格 → 确认主界面/驾驶舱构图 → 确认分层与锚点
    → 小包拼装验收 → 角色准备与踏板资产 → 测试演出资产
    → 发帖/清算/洪流所需素材 → 局外档案与交付打磨
```

这一顺序配合真实界面逐步落地：

```text
主界面 → 角色准备 → 驾驶舱 → 两轮测试 → 结算与机会选择
    → 发帖 → 因果清算 → 原帖/曲解洪流 → 玩家署名结局
```

这只是美术制作顺序，不表示这些页面已经实现，也不改变原阶段计划的玩法依赖。

### 1.2 已确认与待确认

| 项目 | 状态 | 制作约束 |

| 整体 | 已确认 | 全程 2D 卡通恶搞，单机，PC 与移动端 |

| 洪流 | 已确认 | 头像和帖子增多、视觉变嘈杂；可滚动、刷新、查来源；不画独立传播树 |
| 结局 | 已确认 | 多帖聚焦至玩家署名但非玩家原话的一条；优先“崇高化”；安静定格，无系统总结 |
| 媒体 | 已确认边界 | 2D 动画可完成流程，视频只是可替换插槽；本文不授权视频生成 |

### 1.3 不得通过美术新增的内容

- 局内暴躁/疲劳百分比、心率图、L/A/K/T 数字、额外状态图。
- 局内传播数字栏、独立传播树、预算管理、局内重开按钮。
- 隐藏空调/座椅交互的解释箭头、自动闪光提示、第二局必高亮。
- 保证断裂、奖励甜蜜区、油门固定中奖概率等玩法承诺。
- 未经确认的主角对白、旁白、固定声线、血腥恐怖变体。

### 1.4 状态用词

资产采用：**待制作 → 候选 → 作者确认 → 拆分/修图 → 可导入 → 场景验收通过**。

- 生成成功不等于作者确认。
- 作者喜欢参考图不等于所有分层已经能拼装。
- 能导入不等于游戏界面已完成，桌面截图不等于手机真机验收。
- 本文所有资产初始状态均为“待制作”，不得预勾完成。

## 2. 风格如何先定下来

### 2.1 推荐候选，不是定稿

第一轮推荐尝试：**清晰轮廓、平涂为主、少量硬边阴影、适度夸张的大头人物与道具、动作有弹性**。

理由：在小屏上容易看清鞋和踏板，也能用少量动画制造喜剧。清算/洪流的情绪变化通过排版、节奏、遮挡、声音与色彩组织完成，不必把人物突然换成另一种画风。

不要把“卡通”自动解释为像素风、3D 渲染、某款现有游戏的复刻。可以保存拥有使用权的参考图作为视觉坐标，但不依赖真实车标、社交平台标识、名人或未经授权的角色素材。

### 2.2 风格确认表

选定样张后填写；空白字段表示仍待确认，后续 AI 不得自行补成定稿。

| 字段 | 当前决定 |
|---|---|
| 风格版本 | 待定，例如 `style-v1` |
| 主参考图路径 | 待定 |
| 主角外观与身份表现 | 待定 |
| 头身比例 | 待定；只已确认“大头” |
| 描边粗细/颜色/均匀程度 | 待定 |
| 平涂/阴影方式 | 待定 |
| 色板（背景/内饰/角色/交互） | 待定 |
| 灯光方向 | 待定 |
| 表面质感与纹理密度 | 待定 |
| 场景透视与夸张程度 | 待定 |
| UI 主题/字体 | 待定 |
| 角色动画方式 | 待定：分层变形/少量逐帧等 |
| 明确禁止的视觉元素 | 待定 |
| 作者确认日期 | 待定 |

UI 实现前需要重新核对引擎可用主题。当前查阅到的 Astroon 偏宇宙渐变、PixelForge 偏像素、BrawlForge 正文偏蓝色科幻 HUD，**都不能仅凭“卡通”标签就当本项目的已选主题**。本次未采用任何预置主题，未生产 UI 代码。

### 2.3 参考包应该包含什么

建议先建立以下参考项，路径在作者制作后填写：

- 已选风格样张。
- 主角全身、正面与驾驶舱腿脚示意。
- 驾驶舱主构图与必要的踏板特写构图。
- 鞋的展示视图与鞋底判定视图。
- 色板、光照方向与描边说明。

**每次生成都同时携带：风格参考＋该物体/场景的具体参考。** 同一个 seed 不能替代参考图，也不能保证跨模型保持角色身份或图层位置。

## 3. 驾驶舱不是机械切图：按功能分层

### 3.1 拆分准则

遇到一个物体，依次判断：

1. 是否独立移动、旋转、变形、换装或改变状态？是则拆。
2. 是否需要盖住其他层、显示在窗外之后或腿脚之前？是则拆。
3. 是否只是固定装饰？是则尽量合并到背景，避免数百张无意义小图。
4. 是否可点击但外观完全不变？可以留在背景，用独立交互区域，不必强行独立出图。
5. 是否含动态文字/数值？留给 UI，不烘焙进图片。

**完整驾驶舱图先用来确认构图。** 运行时交付的是按功能独立生成/编辑的图层；不是把一张扁平图切几块就假装获得遮挡背后的内容。

### 3.2 主驾驶舱建议分层

以下是参考绘制顺序，最终以构图遮挡关系为准，不是所有场景必须使用的固定层级。

```text
从后到前：
窗外天空/环境
  → 道路与远景（按需要分开，支持移动）
  → 窗外天气效果
  → 驾驶舱内饰底层（地板、固定仪表台等）
  → 独立空调/座椅控件（只有需要外观反馈时才独立）
  → 踏板杆与踏板/油门
  → 玩家腿脚（根据踩踏状态调整遮挡）
  → 窗框/仪表台等前景遮挡
  → 表情特写或动作特效（仅在需要时）
  → UI 控件与文字
```

如果前景框压住了本应可见的脚，不能靠改变判定区域掩盖，应修构图/层级。

### 3.3 每层包含与排除什么

| 资产 ID | 内容 | 必须排除 | 为什么拆 |
|---|---|---|---|
| `cockpit_base` | 地板、固定内饰、仪表台固定部分 | 腿脚、独立踏板、动态文字、活动控件；窗外不烘焙 | 固定部分合并，降低拼装成本 |
| `cockpit_frame` | 窗框、必要的仪表台边沿等前景遮挡 | 窗外、腿脚、踏板 | 给窗外与动作留独立层，形成空间感 |
| `outside_sky` | 天空/环境色层 | 车内、窗框、动态道路 | 天气与环境可变化 |
| `outside_road` | 道路/远景，按构图需要 | 车内、窗框、车标 | 加速/刹车动感；是否循环另验收 |
| `weather_overlay` | 雨点、雨线等透明效果 | 永久阴影和车内内容 | 程序按天气叠加；首包可不做 |
| `ac_control` | 空调控件外观与必要状态 | 刻死的温度数值、解释箭头 | 可操作；显示操作反馈不等于公开隐藏参数 |
| `seat_control` | 能被第一人称看见的调节控件 | 完整座椅大图、状态百分比 | 不必为调节操作画出整把座椅 |
| `brake_rod` | 杆与必要连接结构 | 被烘焙的踏板面、错误的新支点 | 踩踏/断裂可能独立变化 |
| `brake_face` | 踏板实际接触面及装饰 | 杆、鞋、地板、碰撞调试框 | 接触判定与动画锚点需要明确 |
| `throttle_face` | 刹车右侧的油门外观 | 刹车、鞋、夸张警告牌 | 单独识别意外；后果尚未定 |
| `player_legs` | 第一人称裤腿及必要身体部分 | 绑死的鞋型 | 换裤子/鞋不重画整个背景 |
| `player_shoe` | 第一人称可见鞋外观 | 踏板、不可分离的裤腿 | 移动、踩踏与换鞋 |
| `action_fx` | 速度线、冲击线、汗滴等候选 | 文字、固定脚的位置 | 喜剧演出按事件触发，不烘焙在底图 |

### 3.4 容易忽略的“藏在下面的内容”

- 鞋会移动，底图必须补齐鞋原位置下面的地板。
- 踏板会踩下/变形，底图不能留下另一块静止踏板。
- 窗外会变化，窗孔不能预先画死另一套天气。
- 杆会断裂，断口/杆后面的空间需要能显示。
- 透明前景的窗孔应有真实 alpha，不是白色块或棋盘格图片。
- 非透明内饰底图可以和窗孔遮罩共同工作，但窗外层必须有可见通道。

可先让 AI 输出整层可用构图，再用修图/抠图补齐；**删除物体不等于自动获得完美的隐藏背景**，需要实际检查。

### 3.5 主视图与踏板判定视图

驾驶舱主视图需要展示窗外和操作环境；踏板判定需要看清鞋底与踏板。两者未必适合塞进同一个画面。

**推荐候选**：驾驶舱主视图＋进入落点轮时切到脚部区域特写；保持同一内饰、鞋型和踏板身份。这不是增加判定轮，而是同一环节的画面切换。

是否切特写、特写朝向和范围由作者确认。未确认前不要让生成模型自行扭转相机，造成正面踏板、俯视鞋底与斜透视地板互相矛盾。

## 4. 按玩家流程拆资产

### 4.1 主界面

- 入口已确认：**开始测试 / 测试档案**。
- 先做构图参考，运行背景可复用驾驶舱/角色元素，不要求为菜单另画复杂场景。
- 标题、按钮文字、焦点与按下状态由 UI 构建。
- 艺术化 Logo 可以后做；若制作，保留可编辑文字版本，不能把 AI 错字当正式标题。
- 不用宣传海报代替真实主界面，避免按钮只是图上可见但不可操作。

### 4.2 角色准备

两套视图不要混淆：

| 视图 | 用途 | 要求 |
|---|---|---|
| 全身展示 | 选择衣服、裤子、鞋子，建立角色印象 | 固定站姿、同一比例/画布/锚点，各服装可替换 |
| 第一人称腿脚 | 驾驶舱中的移动、踩踏 | 与全身展示是同一个角色和服饰，但按驾驶视角单独出图 |

推荐先做一个身体基准、一套衣服、一条裤子、一双鞋。验证换层和身份一致后，再增加变体；数量待作者确认。

服装分层要注意袖口、腰部、裤脚与鞋口的接缝。不要要求 AI 在一个文件里自动产出可精确拼合的完整纸娃娃系统。

第一人称以腿脚为主，不意味删除已确认的大头角色设计。表情如何出现（特写、镜头切换等）仍是待确认演出方式；不默认在驾驶舱强塞完整角色。

### 4.3 踏板与鞋底

最少交付：

- 刹车踏板面。
- 杆与固定连接点说明。
- 油门。
- 一双可见鞋外观。
- 对应鞋底判定轮廓/几何标注参考。

鞋展示图、第一人称鞋图、鞋底接触几何必须使用同一 `shoeId` 对应身份。鞋底参考图可以有标注，但标注不能出现在运行用 PNG 内。

### 4.4 测试与结算演出

状态需求来自现有设计：正常、变形、根部断裂、连杆断裂。先做结构预案，具体形变程度与触发阈值待定。

制作节约原则：

- 普通踩下优先尝试分层旋转/位移，不先画大量逐帧图。
- 真正不能由变换表达的形变，再出独立状态图。
- 根部断裂与连杆断裂要能看出部位差异；分离件使用一致断口和锚点。
- 急停、鞋移错、人物震动、表情定格可以形成喜剧；不依靠每次同一爆炸特效。
- 力度条必须保持标准长方形，不变成怪物嘴、圆环或新增操作条。
- 结算力度与两种用时由程序显示，不画在结果图片里。

### 4.5 发帖、清算、洪流、结局、档案

| 页面 | AI 图片适合做什么 | 必须由程序处理什么 |
|---|---|---|
| 发帖 | 虚构头像、少量图标、可选手机外框 | 词条、标题/内容、发送、选择反馈、原帖副本 |
| 清算 | 可选纸张纹理/小标识，也可完全不用图片 | 单色等宽文字、真实因果、逐条揭晓、翻页 |
| 洪流 | 统一体系下的一组不同头像、可选媒体缩略图 | 帖子内容、来源链接、滚动/刷新、层级变化 |
| 结局 | 复用玩家头像与已选视觉元素 | 多帖聚焦、玩家署名、非原话文案、安静定格 |
| 档案 | 少量图标/空状态装饰 | 真实历史、因素、时间、发帖与最终结果 |

洪流的“字体不统一/排版混乱”应是**受控递进**：可以变化卡片密度、层级与有限字体组合，但关键原帖、来源按钮、玩家署名和中文字符必须可读，不能以随机错字或无法操作来表达混乱。

不要让 AI 一次生成一张包含几十条帖子的图片作为洪流：那样文字不可追溯、不可滚动、不可更换，也不能维护原帖事实。

## 6. 最重要的技术交付：画面与判定几何一致

### 6.1 不把图片包围盒当碰撞区域

以下都不应自动计入面积：透明留白、外描边、投影、装饰、鞋底缺口、杆。

透明 alpha 可以辅助标出可见轮廓，但**不等于真实施力接触面**；接触几何需要明确标注，并由开发校验。

美术需要提交两份东西：

1. 无调试框的运行图片。
2. 带标注的几何参考：可接触区域、鞋底真实鞋块、杆端支点、踏板连接点与锚点。

### 6.2 共用场景坐标与裁切信息

建议以一张确定的母画布标注坐标，再保存归一化坐标。场景示意二维坐标 x 向右、y 向下；这个约定不修改引擎 3D 坐标系。

- 所有场景层使用同一母画布/构图。
- 踏板判定区域另有自己的局部坐标与屏幕摆放变换，不直接复制旧 Demo 的 `[0,1]` 位置。
- 局部 PNG 裁切后必须记录它在母画布里的原始偏移与锚点。
- 同组踩下/变形状态不能偷偷改变画布尺寸或移动固定支点。
- 不同屏幕上的脚部判定板采用一致的均匀缩放与偏移，不能按宽高分别拉伸后继续使用原距离。

下面只是**拟定交付结构示意**，不是现有 Lua 配置格式，也不是已选几何；空值刻意保留：

```yaml
asset_id: brake_face
style_version: 待确认
reference_canvas: 待记录实际宽高
image_path: 待填
crop_origin_px: 待记录
image_size_px: 待记录
anchor_px: 待标注
scene_pivot_px: 待标注杆端固定支点
rod_attachment_px: 待标注杆与踏板连接点
contact_regions_px: 待标注实际踏板接触面
linked_assets: 待填杆与状态件 ID
approved_by_author: false
```

### 6.3 杆、连接点、支点、受力重心是不同的点

```text
杆端固定支点 ●
             │ 杆（机械结构）
             │
踏板连接点   ○──[踏板面]
                    × 真实受力重心（随鞋底交集改变）

鞋操作锚点/中心：另外记录，不必和 × 重合。
```

- **杆不会因为鞋落点变化就改接到受力重心上。** 固定连接点来自美术/机械结构；受力重心只用于计算。
- 当前 Demo 的线段是开发受力示意，不应原样当作正式驾驶舱的杆动画。
- 支点在杆的一端，不是任意取踏板中心，更不是杆和踏板接缝处。
- L 从真实交集面积重心计算，不能使用屏幕像素距离，也不能把鞋中心当受力点。
- 三维透视的装饰图不能直接推导精确三维扭矩；这里仍是统一的游戏受力示意。

### 6.4 当前规则能力与美术边界

当前 `Landing.lua` 使用单个矩形踏板、可选矩形油门与互不内部重叠的矩形鞋块。正式鞋型和踏板几何仍待确定。

因此：

- 可先制作有清晰主接触面的美术，不必把所有对象画成生硬方块。
- 若最终轮廓需要曲线或多边形，必须同时评估/扩展几何模型；不能悄悄使用巨大外包矩形而宣称真实轮廓判定已完成。
- 分段鞋底缺口必须被保留；不得用完整鞋外轮廓填满缺口。
- 零接触无受力重心，不进入 L/A/T 计算。
- 部分踩空由 `r踏板` 与 `r鞋底` 两个比例反映，不在图片里额外画“隐藏鞋种倍率”。

### 6.5 油门稀有度如何验收

已确认：油门在刹车旁边；只有未接触刹车时接触油门才归为油门意外；同踩两者按当前结构归为刹车并保留双接触事实。后果仍待定。

**不固定采用之前“9.36% / 20.45%”等数作为实际概率。** 那些是旧占位鞋型与摆放在均匀网格下的覆盖统计，不包含游标真实运动分布、上次落点偏好、玩家按停行为，不能证明实际游玩中的稀有度。

稀有度同时受：踏板间距、宽高、鞋底形状、移动区域、运动轨迹与玩家时机影响。缩短长度、缩小宽度、移动位置都可能改变结果，但不能把某一个因素写成普遍唯一规律。

美术定构图后：分别检查几何网格覆盖、真实游标轨迹采样和玩家测试。不要为了稀有把油门挪到不符合已确认现实布局的位置，也不要暗中加随机骰子让视觉命中却算没踩到。

## 7. AI 生成工作流：如何减少返工与身份漂移

### 7.1 每轮生成前做六个检查

1. 本次是参考图还是可导入单件？不要混写。
2. 采用哪份风格版本、哪份构图/物体参考？
3. 画面中只包含哪些元素，明确排除哪些？
4. 相机、光照、尺寸、锚点和对象占画布比例是否固定？
5. 是否需要透明背景，是否需要补齐被遮挡内容？
6. 本次生成能否在不重画其他层的情况下替换进去？

推荐一次生成一个可独立使用的对象/层。同一轮可以批量出数件，但各自应有用途和参考，不让模型一次输出带标签的整张“素材合集”当作运行资源。

### 7.2 构图确认后再出层

1. 先选一张完整构图作为位置参照。
2. 在参照中标出窗孔、动态物体和关键锚点；标注版仅用于制作。
3. 从这张参照编辑/派生独立层，或按同一约束单独生成。
4. 逐层复合，核对尺寸、透视、光照、描边、遮挡。
5. 有偏差就修该层；不要每次重生成整个驾驶舱导致其余几何漂移。

AI 不一定能精确服从“完全相同位置”“透明”或“无文字”。把这些写入提示词后仍须人工抠图、补绘、对齐；交付前不以提示词承诺代替检查。

### 7.3 透明、阴影与镜像

- 棋盘格/纯白背景不是透明，必须查看 alpha 通道或叠到不同底色上测试。
- 阴影可以随物体同层，但碰撞区域不包括阴影；若阴影需独立控制，单独拆层。
- 不建议用整图水平镜像把左脚当右脚：鞋结构、裤脚细节、光照和踏板左右布局可能被镜像错。
- 若需要镜像复用，先确认物体真的可对称，并同步锚点/几何变换；不能只翻图片不翻判定。

### 7.4 动画与状态件

- 先验证静态单件，再制作状态。
- 同组状态使用相同画布、对象身份、相机和固定锚点。
- 逐帧图需要帧顺序、帧数、每帧画布、播放方式与锚点；帧率在实际演出中调校，不先写死。
- 不同服饰的第一人称动作可以共用结构，但不能让生成模型每帧更换鞋型。
- 不把 AI 视频当做唯一实现；视频生成需另有明确请求和工具确认，本轮不执行。

### 7.5 音频与可选视频的交接边界

图像资产不需要携带音轨。后续制作演出时，以下硬约束必须保留：

- 结算前保留 **0.5 秒完全静音**，包含环境声、音效与音乐，不只关闭某一条音轨。
- 金属极限事件音整局不重复滥用，最终结局安静定格。
- 声音素材清单、主角对白、旁白、配音数量与声线尚未确认，旧 BGM 示例不能整体当成批准清单。
- 视频是可替换插槽，缺失/失败也要用 2D 完成相同剧情出口。
- 已有视频参考规格：V1 断裂喜剧 3～5 秒、V2 测试台到手机 2～3 秒、V3 结局 3～5 秒，16:9，首尾各留 0.5 秒缓冲；V1/V3 无音轨，V2 可带环境音。它们不授权现在生成视频，也不允许用时长去伪造“感觉/实际用时”。

本指南主要管理图片美术；开始音频/视频制作时应另列待确认清单，不让图片提示词自动扩展成配音或 CG 任务。

### 8.9 拒收条件

出现以下任一问题，先修再导入：

- 参考身份/鞋型变了，左右颠倒，主角多出肢体。
- 相机、灯光、描边与已选风格不一致。
- 图层包含应属于别层的物体，遮挡背后内容没补齐。
- 非真实透明、透明边缘白边、人物/杆被裁断。
- 任意生成的文字、数据、水印、车标或未经要求的新图标。
- 固定支点/连接点漂移，状态件画布不同而未记录偏移。
- 为了好看变更了踏板/鞋底接触范围，却没有同步几何记录。
