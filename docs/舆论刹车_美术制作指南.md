## 0. 从这里开始：第一轮只做什么

不要一开始生成整套素材。先完成下面的**风格与场景确认**，它们不直接作为游戏运行资产：

1. **风格样张**：同一视觉体系下出现低模角色、低模驾驶舱一角、低模踏板，检查是否属于同一种低模卡通观感。
2. **主界面构图**：明确标题留白、开始测试、测试档案的位置；文字和按钮在游戏中由 UI 实现。
3. **驾驶舱 3D 白盒**：用引擎内置几何体或程序化几何体搭出驾驶舱、踏板、杆、油门的空间关系与第一人称视点，确认尺度、视角、操作可达性。**这是 3D 方案特有的前置步骤**，用于在投入模型制作前验证空间设计。

三图通过后，先做驾驶舱的一个小型 3D 包：**内饰（含地板）＋踏板/杆/油门 ＋ 窗外**。导入后检查画面、尺度、第一人称视角、PC 与手机适配，再继续角色与演出。

**第一轮暂不做**：所有服装变体、全部天气、断裂逐帧动画、几十个头像、宣传图、配音、视频。

制作顺序：

```text
确认低模风格 → 确认主界面构图 → 确认驾驶舱 3D 白盒（尺度/视角/可达性）
    → 驾驶舱 3D 小包验收 → 角色与踏板 3D 资产 → 测试与演出资产
    → 发帖/清算/洪流所需 2D 素材 → 局外档案与交付打磨
```

这一顺序配合真实界面逐步落地：

```text
主界面 → 角色准备 → 驾驶舱 → 两轮测试 → 结算与机会选择
    → 发帖 → 因果清算 → 原帖/曲解洪流 → 玩家署名结局
```

这只是美术制作顺序，不表示这些页面已经实现，也不改变原阶段计划的玩法依赖。

### 1.3 不得通过美术新增的内容

- 局内暴躁/疲劳百分比、心率图、L/A/K/T 数字、额外状态图。
- 局内传播数字栏、独立传播树、预算管理、局内重开按钮。
- 隐藏空调/座椅交互的解释箭头、自动闪光提示、第二局必高亮。
- 保证断裂、奖励甜蜜区、油门固定中奖概率等玩法承诺。
- 未经确认的主角对白、旁白、固定声线、血腥恐怖变体。

### 1.4 状态用词

资产采用：**待制作 → 候选 → 作者确认 → 拆分/修图 → 可导入 → 场景验收通过**。

- 作者喜欢参考图不等于所有分层已经能拼装。
- 能导入不等于游戏界面已完成，桌面截图不等于手机真机验收。
- 本文所有资产初始状态均为“待制作”，不得预勾完成。

## 2. 风格如何先定下来

### 2.1 推荐候选，不是定稿

作者提出的观感方向参考：**PEAK 一类的低模平涂卡通**——低面数几何（保留明显棱角）、纯色或极简光照材质、靠后期调色（饱和度/对比/暗角）统一氛围。

这不是最终定稿，只记录为候选。若采用，理由是小屏容易看清鞋和踏板，低模也让物理散架、拉伸等夸张表现更自然。清算/洪流的情绪变化通过排版、节奏、遮挡、声音与色彩组织完成，不必把人物突然换成另一种画风。

**引擎能力边界（已核实，见 `engine-docs/recipes/surface-shader.md`）**：

| 效果 | 引擎支持情况 | 说明 |
|---|---|---|
| 平涂/纯色材质 | ✅ 稳定可用 | `Techniques/NoTextureUnlit.xml`，materials skill 明确标注 ✅ 卡通 |
| 后期调色（暗角/色调映射/曝光） | ✅ 稳定可用 | Zone 的 Vignette / Tonemap / AutoExposure / Bloom，见 `engine-docs/recipes/rendering.md` |
| 赛璐璐分段明暗（Toon） | ⚠️ **仅 Web 预览版** | 移动端发布前必须实测，不要默认可用 |
| 描边（Outline） | ⚠️ **仅 Web 预览版**，且只支持不透明 | 同上；不要把它当作移动端可依赖的基础观感 |

**因此"低模 + 平涂 + 调色"这套组合是稳的；"Toon 分段 + 描边"在移动端有风险，必须实测后再决定是否依赖。** 在作者选定观感前，不要把任何一项写成已定稿。

不要把“卡通”自动解释为像素风、3D 渲染、某款现有游戏的复刻。可以保存拥有使用权的参考图作为视觉坐标，但不依赖真实车标、社交平台标识、名人或未经授权的角色素材。

## 3. 驾驶舱是 3D 场景，不是分层拼图

> **本节已按 2026-10-15 决策重写。** 原"按功能分层、分层拼装、锚点/裁切标注"的做法在 2D 下成本过高，现改为 3D 低模场景。遮挡、层级、锚点在 3D 里由**节点父子关系与真实空间坐标**表达，不再需要母画布与像素偏移。

### 3.1 为什么 3D 省掉了拼装成本

2D 方案里最麻烦的几件事，在 3D 里自然消失：

| 2D 痛点 | 3D 下的对应做法 |
|---|---|
| 鞋会移动，底图要补齐它下面的地板 | 地板是独立物体，本来就在那里 |
| 踏板会踩下，底图不能留静止副本 | 踏板是独立节点，旋转/位移即可 |
| 杆会断裂，断口后面的空间要能显示 | 杆是独立物体，断开就是移除约束 |
| 窗孔要真实 alpha，不能画死另一套天气 | 窗外是独立空间，天空盒/远景直接可见 |
| 要记录母画布、裁切偏移、锚点、旋转中心 | 直接用世界坐标与节点变换 |
| 换鞋/换裤子要重画并对齐图层 | 替换 mesh 或换子节点 |

**因此 3D 方案下，第 6 节原来那套"图片像素几何标注"不再是主要交付物**，改为"模型 + 场景坐标 + 接触面说明"。

### 3.2 驾驶舱 3D 场景包含什么

按**真实空间关系**组织，而不是绘制顺序：

```text
车辆（外壳 + 内饰）
  ├─ 座舱空间：座椅、仪表台、方向盘
  ├─ 窗外：天空盒 / 远景 / 道路（可滚动或位移）
  ├─ 踏板总成：刹车踏板、杆、油门（各自独立节点）
  ├─ 空调控件、座椅调节控件（可操作实体）
  └─ 玩家（第一人称）：腿脚节点，跟随视角
相机：第一人称，挂在玩家/座位节点下
```

关键约束：

- **踏板、杆、油门各自是独立节点**，因为它们的踩下、变形、断裂需要独立变化。
- **杆有固定支点**，支点在 3D 世界里是一个明确位置，不随受力重心移动。
- **窗外与内饰分离**，天气变化时只替换窗外层。
- **玩家腿脚与角色是同一身份的两种呈现**，不是两个角色。

### 3.3 尺度与第一人称视点

- 引擎长度单位是**米**（见全局开发规则）。角色高度约 1.5～2.0 米，踏板、座椅按真实尺度建模，不要凭感觉缩放。
- 第一人称视点决定"玩家能看到什么"，**必须先用白盒验证**：坐姿眼睛高度、仪表台遮挡范围、踏板是否在视野内、脚部是否可见。
- 内置模型与程序化几何体的尺寸不要猜测，用 `boundingBox` 动态获取（见全局规则 #9.2）。

### 3.4 空调与座椅控件

已确认它们是**可见可操作的实体**，不加解释性箭头、不显示隐藏数值。在 3D 下的实现方式仍待定，候选：

- 作为 3D 场景中的独立小物件（旋钮、按钮、拉杆），可点击/拖动；
- 或作为场景中的热点区域，交互反馈由 3D 形变/位移表达。

具体采用哪种由作者确认，不在本文预先定案。

### 3.5 窗外环境

窗外是 3D 空间的一部分，天气变化通过替换或调整以下内容实现：天空盒颜色/贴图、远景层、雨雪粒子。是否使用滚动道路、滚动速度与加速阶段的关系属演出细节，待作者确认。

## 4. 按玩家流程拆资产

### 4.1 主界面

- 入口已确认：**开始测试 / 测试档案**。
- 主界面是 2D UI，不要求 3D 场景。
- 标题、按钮文字、焦点与按下状态由 UI 构建。
- 艺术化 Logo 可以后做；若制作，保留可编辑文字版本，不能把 AI 错字当正式标题。
- 不用宣传海报代替真实主界面，避免按钮只是图上可见但不可操作。

### 4.2 角色准备

角色准备是**唯一能看到完整角色全身**的环节（驾驶环节是第一人称，只看到腿脚）。

| 视图 | 用途 | 要求 |
|---|---|---|
| 全身展示 | 选择衣服、裤子、鞋子，建立角色印象 | 3D 低模角色，固定站姿，各服饰可替换 |
| 第一人称腿脚 | 驾驶舱中的踩踏表现 | 与全身展示是同一个角色和服饰，但按驾驶视角单独处理 |

推荐先做一个身体基准、一套衣服、一条裤子、一双鞋。验证换装和身份一致后，再增加变体；数量待作者确认。

3D 下换装的做法：身体与服饰是不同 mesh 或不同节点，替换时保持骨架/关节对齐。**不要要求 AI 在一个模型文件里自动产出可精确拼合的完整换装系统。**

### 4.3 踏板与鞋底

最少交付：

- 刹车踏板（3D 形体 + 接触面说明）。
- 杆与固定支点位置说明。
- 油门（3D 形体）。
- 一双鞋的 3D 形体。
- 鞋底接触面说明（用于和判定几何对齐）。

鞋展示、第一人称鞋、鞋底接触面必须使用同一 `shoeId` 对应身份。

**与 2D 的关键差异**：不再交付"鞋底轮廓图片 + 像素标注"，而是交付**模型 + 接触面的空间说明**。判定仍由 `Landing.lua` 的几何负责（见第 6 节），美术提供的是它的 3D 视觉对应物。

### 4.4 测试与结算演出

状态需求来自现有设计：正常、变形、根部断裂、连杆断裂。先做结构预案，具体形变程度与触发阈值待定。

**角色在刹车判定后的身体表现（待探索，非定稿）**

作者要求：刹车判定后，用身体效果表现刹车结果——人飞出去、肢体崩坏、拉伸之类。

本文记录一个候选方案，供作者参考与比较；**作者明确表示仍在探索其他方案，本文不把它当定稿**：

> **候选方案：部件化低模角色 + 关节约束**
>
> - 角色由独立部件组成（头、躯干、上臂、前臂、大腿、小腿、脚），部件之间用物理关节约束连接。
> - 正常驾驶时，部件按预设姿态摆放（关节角度插值），不需要骨骼动画。
> - 刹车判定后，按结果给部件施力并解除部分约束，产生飞出、散架、拉伸效果。
> - 拉伸通过节点缩放实现，低模风格下夸张效果更好。

**该候选方案的已知边界（已核实）**：

- 引擎**没有现成的 Ragdoll API**（`.emmylua/` 中不存在）。
- `Bone` 类型**只读**（`Skeleton.d.lua` 只有 `GetFinalWorldTransform()` 等读取接口，无写入），因此"驱动骨骼做 ragdoll"这条路不通。
- 物理约束可用：`Constraint` 支持 `CONSTRAINT_POINT` / `HINGE` / `SLIDER` / `CONETWIST` 四种。
- **多刚体约束链的稳定性未经实测**，部件多时是否抖动/散架需要技术验证。

其他可能的方案（作者可继续探索）：整体刚体 + 预设动画、顶点形变、视频插槽、纯程序化夸张形变等。**在作者选定前，不要按任何一种方案开始生产角色资产。**

制作节约原则：

- 普通踩下优先尝试节点旋转/位移，不先做大量逐帧。
- 真正不能由变换表达的形变，再出独立状态。
- 根部断裂与连杆断裂要能看出部位差异；分离件使用一致断口和锚点。
- 急停、鞋移错、人物震动、表情定格可以形成喜剧；不依靠每次同一爆炸特效。
- 力度条必须保持标准长方形，不变成怪物嘴、圆环或新增操作条。
- 结算力度与两种用时由程序显示，不画在结果图片里。

### 4.5 发帖、清算、洪流、结局、档案

> **本节保持 2D。** 这些环节本质是文字与排版 UI，3D 化没有收益。它们是当前方案里唯一继续按 2D 制作的部分。

| 页面 | AI 图片适合做什么 | 必须由程序处理什么 |
|---|---|---|
| 发帖 | 虚构头像、少量图标、可选手机外框 | 词条、标题/内容、发送、选择反馈、原帖副本 |
| 清算 | 可选纸张纹理/小标识，也可完全不用图片 | 单色等宽文字、真实因果、逐条揭晓、翻页 |
| 洪流 | 统一体系下的一组不同头像、可选媒体缩略图 | 帖子内容、来源链接、滚动/刷新、层级变化 |
| 结局 | 复用玩家头像与已选视觉元素 | 多帖聚焦、玩家署名、非原话文案、安静定格 |
| 档案 | 少量图标/空状态装饰 | 真实历史、因素、时间、发帖与最终结果 |

洪流的“字体不统一/排版混乱”应是**受控递进**：可以变化卡片密度、层级与有限字体组合，但关键原帖、来源按钮、玩家署名和中文字符必须可读，不能以随机错字或无法操作来表达混乱。

不要让 AI 一次生成一张包含几十条帖子的图片作为洪流：那样文字不可追溯、不可滚动、不可更换，也不能维护原帖事实。

## 6. 最重要的技术交付：画面与判定几何一致

> **本节已按 3D 决策修订。** 2D 下的"图片像素标注 + 母画布偏移"不再适用。3D 下几何是**真实空间坐标**，判定与画面的一致性反而更容易保证——但仍需明确交付"接触面说明"，因为判定仍由 `Landing.lua` 的矩形几何负责（见 6.4）。

### 6.1 不把模型包围盒当接触区域

以下都不应自动计入接触面积：装饰件、外描边、投影、鞋底缺口、杆、模型的空余部分。

**模型的 `boundingBox` 不等于真实施力接触面**；接触几何需要明确说明，并由开发校验。

美术需要提交两份东西：

1. 可导入的运行模型（无调试框、无标注）。
2. 接触面说明：踏板哪个面/区域参与接触、鞋底哪部分是真实鞋块、杆端支点位置、杆与踏板的连接位置。

### 6.2 3D 空间坐标与支点

3D 下不再需要母画布与归一化二维坐标；直接用**场景世界坐标**（单位：米）。但仍要明确记录：

- 车辆/驾驶舱的摆放坐标与朝向。
- 踏板的实际位置、尺寸与接触面朝向。
- **杆端固定支点**的世界坐标（这是 L 计算的关键输入）。
- **杆与踏板的连接点**位置。
- 鞋底接触块的实际尺寸（用于和判定几何对齐）。

**注意**：3D 透视下，屏幕像素距离**不能**用来推算 L。判定仍使用归一化场景坐标下的真实交集面积重心（见 6.3、6.4）。

下面只是**拟定交付结构示意**，不是现有 Lua 配置格式，也不是已选坐标；空值刻意保留：

```yaml
asset_id: brake_assembly
style_version: 待确认
units: meter
axis: { up: Y, forward: +Z }
model_path: 待填
scene_position: 待记录
scene_rotation: 待记录
pivot_world: 待标注杆端固定支点世界坐标
rod_attachment_world: 待标注杆与踏板连接点
contact_surface: 待标注踏板实际接触面
linked_assets: 待填杆与状态件 ID
approved_by_author: false
```

### 6.3 杆、连接点、支点、受力重心是不同的点

```text
杆端固定支点 ●
             │ 杆（机械结构）
             │
踏板连接点   ○──[踏板面]
                    × 真实受力重心（随鞋底交集改变）

鞋操作锚点/中心：另外记录，不必和 × 重合。
```

- **杆不会因为鞋落点变化就改接到受力重心上。** 固定连接点来自美术/机械结构；受力重心只用于计算。
- 当前 Demo 的线段是开发受力示意，不应原样当作正式驾驶舱的杆动画。
- 支点在杆的一端，不是任意取踏板中心，更不是杆和踏板接缝处。
- L 从真实交集面积重心计算，不能使用屏幕像素距离，也不能把鞋中心当受力点。
- 三维透视的装饰模型不能直接推导精确三维扭矩；这里仍是统一的游戏受力示意。

### 6.4 当前规则能力与美术边界

当前 `Landing.lua` 使用**归一化二维矩形**：单个矩形踏板、可选矩形油门、互不内部重叠的矩形鞋块。**3D 场景的引入不改变这套判定**——判定仍在这套二维几何上运行。

因此：

- 3D 踏板与鞋的**视觉形体**可以有圆角、斜面、细节，但**判定接触面要能对应到这套矩形几何**。
- 若最终轮廓需要曲线或多边形，必须同时评估/扩展几何模型；不能悄悄使用巨大包围盒而宣称真实轮廓判定已完成。
- 分段鞋底缺口必须被保留；不得用完整鞋外轮廓填满缺口。
- 零接触无受力重心，不进入 L/A/T 计算。
- 部分踩空由 `r踏板` 与 `r鞋底` 两个比例反映，不在模型上额外做“隐藏鞋种倍率”。

**这是 3D 方案下最容易出问题的地方**：模型看起来是精细的，判定却是矩形。制作前必须明确"视觉形体"与"判定接触面"的对应关系，不要用模型外观去暗示判定精度。

### 6.5 油门稀有度如何验收

已确认：油门在刹车旁边；只有未接触刹车时接触油门才归为油门意外；同踩两者按当前结构归为刹车并保留双接触事实。后果仍待定。

**不固定采用之前“9.36% / 20.45%”等数作为实际概率。** 那些是旧占位鞋型与摆放在均匀网格下的覆盖统计，不包含游标真实运动分布、上次落点偏好、玩家按停行为，不能证明实际游玩中的稀有度。

稀有度同时受：踏板间距、宽高、鞋底形状、移动区域、运动轨迹与玩家时机影响。缩短长度、缩小宽度、移动位置都可能改变结果，但不能把某一个因素写成普遍唯一规律。

3D 布局确定后：分别检查几何网格覆盖、真实游标轨迹采样和玩家测试。不要为了稀有把油门挪到不符合已确认现实布局的位置，也不要暗中加随机骰子让视觉命中却算没踩到。

## 7. AI 生成工作流：如何减少返工与身份漂移

> **本节已按 3D 决策修订。** 3D 下"抠图对齐、母画布拼装"不再是主要工作；改为"生成模型 → 分件 → 导入 → 场景摆放"。但**身份漂移与一致性检查仍然存在**，只是检查对象从图层变成了模型。

### 7.1 每轮生成前做六个检查

1. 本次是参考图/白盒，还是可导入的运行模型？不要混写。
2. 采用哪份风格版本、哪份空间/形体参考？
3. 模型只包含哪些部件，明确排除哪些？
4. 尺度（米）、朝向（Y 上 / +Z 前）、原点位置、面数目标是否固定？
5. 哪些部件需要独立运动，必须分开？（踏板、杆、油门、四肢）
6. 本次生成的模型能否在不重做其他部件的情况下替换进去？

推荐一次生成一个可独立使用的对象/部件。同一轮可以批量出数件，但各自应有用途和参考，不让模型一次输出带标签的整张“素材合集”当作运行资源。

### 7.2 先白盒，再模型

1. 先用引擎内置几何体或程序化几何体搭出**驾驶舱白盒**，确认尺度、第一人称视角、踏板可达性。
2. 白盒通过后，才把白盒里的每个占位块替换成正式模型。
3. 逐件替换，核对尺度、朝向、光照、材质、遮挡。
4. 有偏差就修该件；不要每次重生成整个驾驶舱导致其余部件漂移。

**这是 3D 方案相对 2D 的最大好处**：白盒就是位置参照，不需要"母画布 + 锚点标注"那套间接约定。

### 7.3 尺度、朝向与原点

- **单位是米**。生成后必须核对尺度，不要凭感觉缩放。
- **朝向约定**：Y 上、X 右、Z 前（与引擎一致）。生成模型导入前先确认朝向，不要等到场景里才发现躺倒。
- **原点位置**要明确：部件的旋转轴应落在真实关节/支点上，而不是模型包围盒中心。
- 内置模型与程序化几何体的尺寸用 `boundingBox` 动态获取，不要猜。

### 7.4 材质与观感

- 平涂/纯色材质是稳定选择（`Techniques/NoTextureUnlit.xml`）。
- Toon 分段与描边**仅 Web 预览版**，移动端发布前必须实测；不要默认可用。
- 后期调色（暗角、色调映射、曝光、Bloom）通过 Zone 配置，是稳定能力。
- 低模风格下，**面数与棱角本身就是观感的一部分**，不要为了"更精细"而盲目提高面数。

### 7.5 动画与状态件

- 先验证静态模型，再制作状态。
- 同组状态（正常/变形/断裂）使用相同尺度、朝向、关节位置和原点。
- 角色动画方式待定（见第 4.4 节）；**在作者选定前不要按任何一种方案开始生产角色资产**。
- 不把 AI 视频当做唯一实现；视频生成需另有明确请求和工具确认，本轮不执行。

### 7.6 音频与可选视频的交接边界

模型资产不需要携带音轨。后续制作演出时，以下硬约束必须保留：

- 结算前保留 **0.5 秒完全静音**，包含环境声、音效与音乐，不只关闭某一条音轨。
- 金属极限事件音整局不重复滥用，最终结局安静定格。
- 声音素材清单、主角对白、旁白、配音数量与声线尚未确认，旧 BGM 示例不能整体当成批准清单。
- 视频是可替换插槽，缺失/失败也要用 2D 完成相同剧情出口。
- 已有视频参考规格：V1 断裂喜剧 3～5 秒、V2 测试台到手机 2～3 秒、V3 结局 3～5 秒，16:9，首尾各留 0.5 秒缓冲；V1/V3 无音轨，V2 可带环境音。它们不授权现在生成视频，也不允许用时长去伪造“感觉/实际用时”。

本指南主要管理视觉资产；开始音频/视频制作时应另列待确认清单，不让视觉提示词自动扩展成配音或 CG 任务。

### 8.9 拒收条件

出现以下任一问题，先修再导入：

- 身份/鞋型变了，朝向错误，尺度不是米制，主角多出肢体。
- 材质、光照与已选风格不一致。
- 需要独立运动的部件被合并成一个整体（踏板与杆粘连、四肢粘连）。
- 原点不在关节/支点上，导致旋转轴错误。
- 任意生成的文字、数据、水印、车标或未经要求的新图标。
- 固定支点/连接点漂移，状态件尺度或朝向不同而未记录。
- 为了好看变更了踏板/鞋底接触范围，却没有同步接触面说明。
- 为追求“精细”而盲目提高面数，破坏了低模观感。
