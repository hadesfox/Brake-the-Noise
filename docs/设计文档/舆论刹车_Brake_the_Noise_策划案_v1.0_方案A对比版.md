## 1. 设计公理（贯穿全案，不许违背）

| # | 公理 | 说明 |
| --- | --- | --- |
| A1' | **局内不可预知，局外可追溯** | 玩的时候什么都看不到；玩完可在「测试档案」查到全部因素数据。（v0.4 修订，原为"完全不可见"——走过头会让玩家觉得游戏乱做） |
| A2 | **有限机会** | 测试上限 3 次（3 台车）。"再测一轮"必须付出代价 |
| A3 | **乘法不做加法** | 各因素用乘积耦合，任一失控即可翻倍 |
| A4 | **玩家是操作者，不是观察者** | 三个环节都必须有输入，禁止零互动段落 |
| A5 | **不做循环** | 单次闭环，一局一个故事，玩家的结局是唯一结局 |
| A6 | **品牌匿名 + 数值模糊** | 不点名、不精确复刻，规避风险 |
| A7 | **AI 是增强，不是地基** | 必须有纯模板 fallback，断网可玩 |
| **A8** | **喜剧要真诚** | 第一幕必须真的好笑，第三幕的反思才成立。不能"装喜剧骗人" |

## 3. 第一幕：测试台

### 3.1 显性因素（玩家操作，3 轮判定）

| 轮 | UI | 操作 | 影响 | 取值范围 |
| --- | --- | --- | --- | --- |
| ① 落点 | 踏板横截面，游标左右扫 | 停下 | 力臂系数 L | 0.6 \~ 2.2 |
| ② 接触面 | 脚掌图标缩放/旋转 | 停下 | 压强系数 A | 0.5 \~ 1.8 |
| ③ 力度 | 竖直力度条上下扫（**来回扫**） | 停下 | 峰值 F (N) | 100 \~ 1600 |

**手感基调**

- 游标**来回扫**（非单向），压迫感从机制里长出来，不靠美术吓人
- 判定条本身即教程，不做额外引导
- 三轮之间**节奏紧凑**，每轮 1\~2 秒内做决定

**反馈设计（关键）**

- 前两轮判定完 → 闪绿/红，明确告知好坏
- **第三轮判定完 → 什么都不显示**
- 玩家不知道这一轮成败，只能往下走 → 悬而未决感累积

### 3.2 隐藏因素（玩家不可见，8 个）

| 变量 | 来源 | 效果 | 权重层 |
| --- | --- | --- | --- |
| k1 加载速率 | 上轮停手到本轮开始的时间 | 越急躁 K 越大 | 副 |
| k2 方向 | 输入抖动幅度 | 抖动越大 K 越大 | 副 |
| k3 疲劳 | 累积测试次数 | 次数↑ → 最佳区间收窄 | **主** |
| k4 姿势 | 椅子高度（场景预设） | 影响 L 基准 | 装饰 |
| k5 生理 | 局内时间流逝 | 影响 A 基准 | 副 |
| k6 预期 | 舆论密度（首轮=0） | 影响 k3 累积速度 | **主** |
| k7 温度 | 空调设定（场景预设） | 低温 → K 方差变大 | 副 |
| k8 保养 | 灰尘/检修标签（场景预设） | 影响断裂阈值 | 装饰 |

**权重分层原则**

- **主变量**承担玩家的"感觉"（越来越难了）
- **副变量**制造"有些时候特别容易崩"的波动
- **装饰变量**承担二周目的"惊叹"（原来这些也有影响）

> ⚠️ 玩家感知带宽 = 3。系统里有 11 个因素，但**玩家第一周目能感知的必须 ≤ 3 个**。

### 3.3 结算公式

```
实测扭矩 T = F × L × A × K
其中 K = k1 × k2 × k3 × k4 × k5 × k6 × k7 × k8
```

**为什么必须乘法**：加法让每个因素都不致命，玩家感觉不到谁重要；乘法让任一变量的极端值自动产生戏剧性——**戏剧性是长出来的，不是脚本安排的**。

### 3.4 断裂判定

```
踏板余量  M = M0 − Σ(疲劳损耗) − 保养损耗
M0 初始 = 1000（暂定，待调）

if T > M:  → 断裂
   断裂方式由 T/M 的比值决定：
     T/M < 1.5  → 根部断
     T/M ≥ 1.5  → 连杆断
     临界区     → 未断但变形（最妙的状态）
else: → 未断
```

### 3.5 有限机会（★ 核心设定的前提）

- **3 次测试机会**
- 每测一轮，余量递减
- 第 3 次后**强制发帖**（不允许继续）
- 但玩家可以在第 1 次后就发帖（**这是赌博**）

**决策点心理**：

| 再测一轮 | 直接发帖 |
| --- | --- |
| 可能踩出更炸裂的数据（爆料力↑） | 保住现有数据 |
| 但可能踩断（踏板只有一块） | 但缺乏戏剧性 |
| 每测一次，状态在变差 |   |

## 4. 第二幕：发帖

### 4.1 词条系统（核心机制）

**原则：数据解锁词条（系统定），拼句子（玩家定）**

| 数据来源 | 解锁词条示例 |
| --- | --- |
| 峰值力度 | 「1480N」「我踩到 1400 多」 |
| 断裂状态 | 「断了」「没断」「它变形了」 |
| 操作特征 | 「我犹豫了」「我一下就踩下去了」 |
| 测试次数 | 「我测了好几次」「我只测了一次」 |
| 隐藏因素痕迹 | 「当时感觉不太对」「说不清」 |

**为什么这样设计**

- 词条是玩家的行为**挣来的** → 数据驱动 ✅
- 拼法是玩家的 → 第一人称 ✅
- 避免了"系统替你说话"的体验断裂

### 4.2 发送时机

- 时间轴上有**敏感度曲线**在跑
- 玩家**看不见具体数值**，但能感知"信息流的稀疏程度"
- 停在哪一刻发送 → 决定初始传播势能

**机制要点**

> 同一句话，不同时间发，结果完全不同。
> 早发没事，晚发爆炸。玩家会亲身体验"我说得没错，只是时候不对"。

### 4.3 帖子定性（决定曲解方向）

| 玩家强调 | 曲解方向 | 舆论定性 |
| --- | --- | --- |
| 力度 | 操作问题 | 测试方法有争议 |
| 断裂 | 质量问题 | 设计/制造缺陷 |
| 感觉 | 阴谋论 | 有人说谎 |

## 5. 第三幕：舆论洪流（A + B）

### 5.1 演出顺序（★ 不可颠倒）

```
【节点 1】因果清算（A）— 冷静视觉
  单色 / 等宽字体 / 报告式排版
  逐条揭晓：
    "你在第 2 轮选择了『斜踩』"
    "隐藏因素『疲劳』在第 3 次测试时达到临界"
    "你踩出了 1480N"
    "你发的帖：『我踩断了它』"
  → 玩家此时：理解了因果链 ✅

【节点 2】你的原帖出现 — 孤零零一条
  在信息流的最底部
  → 玩家此时：确认"这是我的" ✅

【节点 3】信息流蔓延（B）— 嘈杂视觉
  彩色 / 多头像 / 字体不统一 / 排版混乱
  帖子一条条往上冒，越来越偏
  → 玩家此时：开始不安（这些我都没说过）

【节点 4】传播树定格
  靠出现顺序隐含传播层级（不画连线，省 1.5 天）

【节点 5】世界说结局
  顶部一条帖，总结了一切
  署名：**你**
  内容：你从未说过的话
  → 玩家此时：这不是我说的
```

### 5.2 曲解三档递进

| 档 | 机制 | 示例 |
| --- | --- | --- |
| 轻微 | 换词、加语气 | 「我踩断了它」→「我踩断了它！」 |
| 中度 | 添加因果、添加立场 | →「我踩断了它，这设计有问题」 |
| 重度 | 变成口号、变成符号 | →「#我踩断了它# 抵制」 |

**档位判定**：传播层级 1 轮 → 轻微；3 轮 → 中度；5 轮+ → 重度

### 5.3 结局落点（★ 已定）

**顶部那条帖：署名是玩家自己，内容是他从未说过的话。**

三个方向（择一或组合）：

| 方向 | 效果 | 情感 |
| --- | --- | --- |
| (A) 极端化 | 改成最激烈的版本 | 恐怖 |
| (B) 反向化 | 意思完全反过来 | 荒诞 |
| **(C) 崇高化** | 把玩家神化成符号 ← **当前选择** | 讽刺 |

**(C) 为什么最狠**

> 最恐怖的不是被曲解，是被神化——
> 你成了一个你从未想成为的人，而且无法否认，因为**那些人说的是真心话**。

**最后不加任何系统总结。定格，结束。**

## 6. 美术与音效

### 6.1 美术资源优先级（**别做精细车模**）

| 优先做 | 不要做 |
| --- | --- |

### 9.5.4 情绪曲线（关键设计）

```
强度
 ▲
 │                    ╱╲  ← 刹车瞬间（"吱"）
 │                   ╱  ╲
 │                  ╱    ╲___  ← 0.5秒静音（真空）
 │        ╱╲      ╱
 │       ╱  ╲    ╱
 │      ╱    ╲  ╱
 │  ___╱      ╲╱
 │ ╱                    ╱╲╱╲╱╲  ← 传播蔓延（阶跃式失控）
 │╱                    ╱
 └────────────────────────────────────────▶ 时间
   上车   测试轮        发帖   传播      结局
```

**关键：**

- **测试轮**是"锯齿状"起伏（每次判定都是一次小高潮）

- **传播蔓延**是"阶跃式"（不是线性上涨，是突然翻倍）
- **结局**是"骤降然后拉平"（聚焦，然后静止）

## 13. 力度条：心理曲线（v0.4 细化）

### 13.1 设计本意（作者原意）

> 人在慌乱时会猛踩。急着踩（前面）力度大，来不及了（后面）力度也大，
> 中间比较冷静，力度小。

```
慌张              冷静              慌张
（急着踩）       （从容）         （来不及）
   ↖                                    ↗
    ╲                                  ╱
     ╲                                ╱
      ╲_____________________________╱
      两端：力度大        中间：力度小
```

**这个曲线本身就是隐性引导**——玩家会本能地追求"中间"（因为看起来安全）。

### 13.2 让它"活"起来（关键）

**曲线形状固定，但"陡峭程度"和"位置"由隐藏因素决定：**

| 状态 | 曲线变化 | 效果 |
| --- | --- | --- |
| 冷静 | 平缓，中间区间**宽** | 容易命中 |
| 暴躁（温度高/天气差/上一轮失手） | 陡峭，中间区间**窄** | 难以命中 |
| 疲劳 | 整体**上移**，最低点也偏大 | 想轻也轻不了 |

**所以：玩家想找"中间"，但中间每次都不一样宽。**

### 13.3 视觉反馈（让玩家"看见自己的心"）

**不显示数字，但游标的运动方式反映状态：**

| 状态 | 游标表现 |
| --- | --- |
| 冷静 | 匀速、从容 |
| 暴躁 | **会抖、会加速** |
| 疲劳 | **移动变慢**（反应迟钝） |

**正反馈闭环**：游标一抖 → 玩家更紧张 → 更暴躁 → 游标抖得更厉害。

| 轮 | 判定 | 时长 | 对应因素 | 操作 |
| --- | --- | --- | --- | --- |
| ① | **落点（含接触面）** | 6s | 力的作用点 + 接触面积 | 鞋底虚影在脚踏区移动 → **点击按停** |
| ② | **力度** | 8s | 峰值力度 | 心理曲线条 → **点击按停** |

**单轮时长：约 14 秒**（原 3 轮约 24 秒）

### 14.1 砍掉第三轮的连带影响（★ 必须处理）

**问题**：第三轮原本是"疲劳累积"的主要表达出口。砍掉后疲劳失去出口。

**解法**：**疲劳 + 暴躁 两个因素，共同作用到力度条上。**

| 因素 | 对力度条的影响 |
| --- | --- |
| **暴躁** | 力度曲线**变陡峭**（低平区变窄）+ 游标**会抖、会加速** |
| **疲劳** | 力度曲线**整体上移**（想轻也轻不了）+ 游标**移动变慢**（反应迟钝） |

**两个因素，两条独立的泄露渠道，互不干扰。**
**一个因素不变，另一个在变 → 玩家感知模糊，归因困难。** ✅ 符合"不可预知"

**⚠️ 两者不得混淆成一个"状态值"** —— 必须保持两个独立变量，否则会退化成单一难度条。

### 14.2 判定轮 ① 的完整设计

**作者原案：落点的鞋底虚影与刹车踏板的重合部分 = 接触面。**

**一次操作，同时产出两个因素：**

| 产出 | 定义 |
| --- | --- |
| **落点** | 虚影中心的停靠位置 → 决定力臂 |
| **接触面积** | 虚影与踏板的重叠面积 → 决定压强 |
| **鞋子的意义** | 不同鞋子的**虚影形状不同** → 直接改变重叠面积 |

**所以"选鞋子"这个开局决策，在这里兑现。** ✅

**虚影移动规则：**

- 随机移动 + **偏向上次踩的位置**（"搁脚习惯"——身体的，不是算法的）

### 14.3 第三轮的预留（将来可加回）

**原 v0.5 设计「压力维持条」保留在此，供将来参考：**

```
力度选定 → 力度条锁定
      ↓
【出现第二根条：压力条】
  从 0 自动上涨（你踩下去了，压力在累积）
  玩家点击一次，停在"刚好"的位置
      ↓
  停太高 → 踏板断裂    停太低 → 滑出去
```

**加回的条件：如果测试后发现"2 轮的赌不够"，再启用。**

## 15. 力度条：心理映射条（v0.5 最终版）

### 15.1 设计原则（★ 作者定调）

> **"要从心理上出发，要以人的本性出发。"**

**这不是数值条，是心理映射条。**

| 玩家的心理 | 力度条上的位置 | 力度 |
| --- | --- | --- |
| 急着踩（慌乱） | 一端 | 大 |
| 冷静从容 | 中间 | 小 |
| 来不及了（慌乱） | 另一端 | 大 |

### 15.2 形状与变化（v0.5 澄清）

**❌ 不做异形。✅ 标准长方形。**

```
┌────────────────────────────────────┐
│                                    │
│  ╲                              ╱  │  ← 数值分布：两端大
│   ╲                            ╱   │
│    ╲___________________________╱   │  中间低平
│                                    │
└────────────────────────────────────┘
      ↑                        ↑
   太早（急）              太晚（急）
```

| 项 | 是否变化 |
| --- | --- |
| 条的**外形** | ❌ 不变（标准长方形） |
| 数值的**分布形状**（两端大中间小） | ❌ 不变（心理模型） |
| 中间"低平区"的**宽度** | ✅ **变**（暴躁 → 变窄） |
| **甜蜜点位置** | ✅ **变**（每轮漂移） |

**一句话：标准的条，但里面的刻度在变。**

### 15.3 隐藏状态只通过"游标运动学"泄露（★ 硬约束）

**❌ 禁止**：显示"暴躁 48%"、心率图、任何数值或图形化的状态指示

**✅ 只允许**：力度曲线的**陡峭度** + 游标的**运动方式**

| 因素 | 曲线影响 | 游标表现 |
| --- | --- | --- |
| **暴躁** | 变陡峭（低平区窄） | **会抖、会加速** |
| **疲劳** | 整体上移（最低点也偏大） | **移动变慢**（反应迟钝） |

**"我说不出哪里不对，但就是不对"** —— 这是荒诞恐怖的原料。

**正反馈闭环**：游标一抖 → 玩家更紧张 → 更暴躁 → 抖得更厉害。

**⚠️ 实现约束**：暴躁与疲劳必须是**两个独立变量**，不得合并为单一"状态值"。

## 16. 三台车机制（v0.5 修正）

### 16.1 机会结构

**上限 3 次测试**。买车只是提供**平等的三次机会**，不是策略资源。

| 路径 | 过程 | 数据特征 |
| --- | --- | --- |
| **不坏路线** | 测 3 次，都没断 | 数据丰富但**平淡** |
| **断裂路线** | 断了 → 换下一台 → 继续；最多 3 台 | 数据**极端**，可能单薄 |

### 16.2 ⚠️ 关键修正（v0.5）

**原措辞（v0.4，错误）**：

> "玩家会主动追求'断'，因为断才有料"

**修正后（v0.5，作者澄清）**：

> **断裂 = 多因素耦合的意外结果，不是可追求的目标。**
> 玩家会**期待**断，但**无法控制**它。

**这个修正为什么重要：**

| 错误理解 | 正确理解 |
| --- | --- |
| 玩家能"故意"踩断 → 变成策略游戏 | **断裂是意外** → 保持"不可控" |
| 三次全断是"刷"出来的 | **三次全断是天选的** → 爆点更珍贵 |

**所以"三台全断"这个最炸的标题，应该是极其罕见的运气。** 玩家玩 10 次可能只见到 1 次。
**这样它才配得上"还原新闻梗"的分量。**

### 16.3 断裂时机决定词条

| 情况 | 解锁词条倾向 |
| --- | --- |
| **首次就断** | 极端但单薄的词条（"第一台就断了"） |
| **后续测试才断** | 数据丰富 + 结果炸裂（最有料） |
| **三次全断** | 🥇 标题最炸（《三台XXX，刹车踏板支架断裂》） |

### 16.4 买车的处理

**⚠️ 不做"预算"UI（违背公理 A1）。**

买车做成**叙事动作**（"我又调来一台"），不做资源管理。
玩家感觉是"继续测"，不觉得"在花钱"。

### 16.5 标题设计（v0.5 补充）

**标题池 ≠ 内容池：**

|   | 词条来源 | 示例 |
| --- | --- | --- |
| **标题** | 结果导向（最炸的信息） | 《三台XXX，刹车踏板支架断裂》 |
| **内容** | 过程导向（细节） | 「第三次测试」「我犹豫了很久」「车里有异响」 |

**🥇 最炸的标题（三次全断）还原新闻梗——《三台XXX，刹车踏板支架断裂》。**
**⚠️ 品牌必须模糊化（A6）。**

## 17. 数据可见性（v0.4 定案）

### 16.1 为什么必须给数据

**如果全程不可见，玩家会觉得"这游戏是乱做的"。**

三幕全都"不可见"的结果是：玩家认为这是随机数生成器。

**所以公理 A1「完全不可见」需要修正为——**

> **A1'（修订）：局内不可预知，局外可追溯。**
>
> - 玩家玩的时候：什么都看不到
> - 玩家的目标不是"学会规则"，而是"感受失控"

### 16.2 分层设计

| 层 | 内容 | 位置 |
| --- | --- | --- |
| **局内** | 只有操作感知（游标抖动、踏板异响、角色的表情） | 游戏过程中 |
| **局外** | **完整因素数据**（力度、落点、疲劳、温度、暴躁值…） | 主界面「测试档案」 |
| **结局** | 清算段提及但不给数值 | 第三幕 |

### 16.3 效果

| 周目 | 玩家行为 | 体验 |
| --- | --- | --- |
| 第 1 局 | 什么都不懂，纯体验 | **恐怖** |
| 第 2 局 | 去档案翻，"原来温度也有影响" | **着迷** |
| 第 3 局 | 开始主动实验（点空调、换鞋） | **涌现成立** |

> **设计灵魂："你玩的时候什么都不知道，玩完才发现一切都有解释。"**

### 16.4 测试档案 = 成就系统

「测试档案」同时承担两个功能：

- **成就收集**（记录玩过几次、见过哪些结局）
- **数据展示**（每次测试的完整因素）

**两个需求合一，省一套系统。**

### 16.5 主界面结构

```
【开始界面】
  ┌──────────────┬──────────────┐
  │  开始测试     │  测试档案     │
  └──────────────┴──────────────┘

【测试档案】
  ┌─────────────────────────────────┐
  │  第 1 次测试  2026-10-13         │
  │    力度 1420N ｜ 落点 偏右        │
  │    疲劳 62% ｜ 温度 28℃          │
  │    暴躁 48% ｜ 结果：踏板断裂      │
  ├─────────────────────────────────┤
  │  第 2 次测试  ...                │
  └─────────────────────────────────┘
  （含隐藏因素的完整数据）
```

## 18. 结算展示：感觉用时 vs 实际用时（v0.5 新增）

### 18.1 要解决的问题

**核心恐怖是"我无法确认我自己"。**

但前三幕里，玩家对这句话的感受是**抽象的**——他"知道"自己判断不准，但**没有具身体验**。

**这个结算展示，就是把这句话具身化。**

### 18.2 界面设计

```
【本次测试结果】

  踩踏力度    ─────────●──────  1420N

  刹车耗时
    你感觉的    2.3 秒
    实际        0.8 秒        ← 高亮
```

### 18.3 玩家的三层心理反应

| 层次 | 内容 |
| --- | --- |
| 第一层 | "差这么多？" |
| 第二层 | "我当时明明觉得很久" |
| **第三层** | **"如果我的感觉这么准不准，那我之前的判断算什么？"** |

**第三层就是切入点。它不解释，只展示；玩家自己得出结论。**

### 18.4 为什么比"只显示实际值"好

| 方案 | 玩家感受 |
| --- | --- |
| 只显示"0.8 秒" | "哦，挺快的" → 无关痛痒 |
| 显示"感觉 2.3 / 实际 0.8" | **"我的感觉骗了我"** → ❗ 直接命中主题 |

### 18.5 "感觉用时"从哪来（★ 关键实现，v0.6 定案）

**采用：系统记录玩家的真实反应时间。**

| 项 | 定义 |
| --- | --- |
| **感觉用时** | 从「力度锁定」到「结算界面出现」的**真实墙钟时间** |
| **实际用时** | 游戏内模拟的刹车时间（可能只有 0.8 秒） |

**⚠️ 上限保护（v0.6 新增）**：

| 方案 | 效果 |
| --- | --- |
| (A) 不设上限，记录真实时间 | 发呆的玩家会看到"你感觉用了 12 秒" ⚠️ 可能觉得是 bug |
| **(B) 设上限（4 秒），超出按 4 秒算** | 🥇 **采用** |

**理由**：目标是"1.5x\~3x 的可信误差"。超过这个范围会显得假。
**上限 4 秒**（即感觉用时最大显示 4.0 秒）。

**为什么这样最妙**：玩家**真的**觉得过了很久（因为他紧张），而游戏内时间是压缩的（子弹时间）。
**所以"感觉 2.3 秒"是真的。** 玩家会愣住，因为他意识到——**这 2.3 秒是他的身体给出的答案。**

### 18.6 与"子弹时间"的关系（★ 这是设计的升华）

**子弹时间在游戏内是"一瞬间"，但在玩家体感上是"好几秒"。**

**所以"感觉 vs 实际"本质上是在问玩家：**

> **"你以为你只做了一瞬间的操作，但你的身体告诉你，你做了很久。"**

**子弹时间从"特效"变成了"证据"。**

### 18.7 展示规则

- 只在结算段展示，**且只展示这一次，不做任何解释**
- **不写"为什么会有差异"**（那会变成科普）
- 只展示两个数字并列
- 下一个界面就是决策点，玩家带着疑问继续

### 18.8 ⚠️ 风险控制

**如果差异太夸张（4 倍以上），玩家会觉得是 bug。**

**控制在 1.5x \~**** 3x 之间。** 这个倍数在心理学上是"可信的误差"（人对时间的感知误差本来就是 2\~3 倍）。

## 20. 美术风格与喜剧设计（v0.4 定案，v0.6 补充视频方案）

### 20.0 喜剧实现的三种手段（v0.6 新增）

**作者方案：2D 动画优先，做不出来的用 AI 视频补充。**

| 手段 | 成本 | 适用 | 优先级 |
| --- | --- | --- | --- |
| **① 2D 逐帧动画** | 中 | 大部分喜剧动作 | 🥇 主力 |
| **② AI 视频动画** | 作者擅长 | 2D 做不出效果的夸张场面 | 🥈 补充 |
| **③ 定格 + 表情** | 极低 | 喜剧停顿 | 🥇 必做 |

### 20.0b ★ 视频插槽规格（v0.6 新增）

**⚠️ 关键：内容后面填，但接口现在定。**

如果不预留插槽，后面硬塞视频会导致：分辨率不搭、转场硬切、音频打架、时机错位。

| # | 位置 | 用途 | 规格 |
| --- | --- | --- | --- |
| **V1** | 第一幕：踩断瞬间 | 喜剧高潮（夸张断裂 + 人飞出去） | 3\~5s，16:9，**无音轨**（BGM 由游戏控制） |
| **V2** | 转场：测试台 → 手机 | 空间转移 | 2\~3s，16:9，可带环境音 |
| **V3** | 结局定格 | 情绪收束（可复用素材） | 3\~5s，16:9，**无音轨** |

**选这三个位置的理由**：它们本来就是"该切场景"的地方，插视频不破坏节奏。

**⚠️ 制作要求**：

- 分辨率与游戏画幅一致（16:9）
- 色温/色调向 2D 卡通靠拢（避免 AI 视频的"写实感"突兀）
- **V1、V3 不加音轨**，音频层统一由游戏控制
- 首尾各留 0.5s 缓冲，便于转场衔接

### 20.1 风格

| 项 | 决定 |
| --- | --- |
| 风格 | **全程 2D 卡通恶搞** |
| 角色 | **大头角色**（表情占比大 = 喜剧感强） |
| 参考 | PEAK / How to Fish / RV There Yet / 60 Seconds |
| 挡风玻璃 | 2D 表现，负责"开车和刹车的画面动感" |
| 驾驶舱 | 2D 场景，**空调/座椅可点击操作**（不做 3D 交互） |

### 20.2 喜剧来自"机制失控"，不是画风

| 喜剧元素 | 来源 |
| --- | --- |
| 踏板飞出去 | 物理失控 |
| 人摔出去 | 姿态滑稽 |
| 慢动作里摆出奇怪姿势 | 时间凝固 |
| 刹车时表情逐渐扭曲 | 表情动画 |

**2D 的优势**：夸张不受限（人可以被弹飞成一条线）、表情成本低、可以卡帧做喜剧停顿。

### 20.2b 🥇 2D 喜剧的四个手法（v0.5 补充）

**核心原则：2D 喜剧的杀招是"帧数控制"，不是"画面精细度"。**
**3D 低模靠"模型荒诞"，2D 靠"动画节奏"。**

| 手法 | 怎么做 | 效果 |
| --- | --- | --- |
| **① 表情定格** | 刹车瞬间，角色表情**卡住 0.3 秒**（瞳孔缩小、嘴巴张开） | 喜剧停顿 |
| **② 肢体橡皮化** | 手臂拉长、身体折成奇怪角度 | 物理夸张 |
| **③ 动作降帧** | 关键动作只画 3\~4 帧，做出"卡顿感" | 廉价但爆笑 |
| **④ 意外静止** | 高速运动突然静止 | 反差 |

**范例场景（可直接实现）：**

> 角色踩刹车时，先做一个**非常自信的姿势**
> → 踏板飞了
> → **角色的姿势保持 1 秒不变**
> → 然后眼睛才慢慢看向镜头

**这个"1 秒不变"就是 2D 的杀招。3D 很难做，2D 一个静止帧就搞定。**

**参考坐标：**

| 类型 | 参考 |
| --- | --- |
| 游戏 | **Happy Wheels**（最接近）、QWOP、Getting Over It、Untitled Goose Game、Learn to Fly |
| 动画 | **《猫和老鼠》**（祖师爷）、Looney Tunes（物理规则失效）、Rick and Morty（荒诞+突然严肃） |
| 3D 低模参考 | Human Fall Flat、Gang Beasts（看它们的"软塌塌"感如何转成 2D） |

### 20.3 ★ 双段式情绪设计（核心）

> **先给玩家错觉是喜剧恶搞游戏，再在舆论环节加上反思。**

| 段落 | 玩家感受 | 手段 |
| --- | --- | --- |
| 第一幕 | **真的好笑的物理喜剧** | 踏板飞、人摔、滑稽慢动作 |
| 第二幕 | 还是好笑的 | 拼词条本身有恶搞感 |
| 第三幕前 30 秒 | 还是好笑的 | 网友评论很贱 |
| **第三幕中段** | **笑声开始变味** | 发现这些好笑的评论说的不是你 |
| 结局 | **完全安静** | 聚焦 + 定格 |

**⚠️ 硬约束：喜剧必须是真诚的喜剧，不能是"装的"。**

### 21.1 L：正面杆端支点与交集面积重心

```text
杆端支点 ● ───── 刹车杆 ───── [踏板面]
                                   ∩ 鞋底真实接触区域
```

- 支点在刹车杆的一端，**不是杆与踏板面的连接点**。支点、杆、踏板、鞋底共用归一化场景几何，再统一映射到界面；窗口尺寸或DPR改变不改变L。
- 所有有效接触统一以鞋底与踏板的**真实交集面积重心**作为受力位置。鞋中心仍记录为操作落点；不在鞋中心跨出踏板边界时突然切算法。
- 多块鞋底逐块求交，面积为`a_i`、块中心为`c_i`：`受力重心=Σ(a_i×c_i)/Σa_i`。缺口不计入面积，不使用鞋底包围盒中心代替。
- 零交集没有受力重心，不除零，不计算L/A/T。支点正式坐标、参考力臂尺度、L范围与映射曲线待填，不能用显示像素距离作为正式系数。
- 正面图是游戏受力示意，不从二维投影宣称得到严格三维扭矩。

### 21.2 A有效：载荷集中 × 接触传导（结构已确认）

保留“小接触面导致局部压强集中”的方向，但A是**有界游戏载荷集中系数**，不是Pa单位的实测压强，不用无上限`1/r`。

```text
交集面积 = 鞋底真实块与踏板的交集总面积
r踏板 = 交集面积 / 踏板面积
r鞋底 = 交集面积 / 鞋底总面积
未接触鞋底面积 = 鞋底总面积 − 交集面积
未接触比例 = 1 − r鞋底

A有效 = A集中(r踏板) × E传导(r鞋底)
```

- **联合结构已由作者确认，不再作为待选方案。** A有效放入原载荷公式的A槽，不能在最终结果另外乘一次E。
- A集中随踏板覆盖减少表达集中效果，具有有限上限。E为零到一的有界传导效率，充分接触接近一，接触减少时降低；它不是新的随机K。
- 小鞋底（如高跟鞋有效小块）充分踩中：r踏板小、r鞋底高，载荷集中且传导较充分。
- 大鞋底只擦到踏板一角：r踏板小、r鞋底低，需有效传导衰减，不能与小鞋充分接触得到同一危险结论。
- 未接触面积/比例用于区分接触完整程度，不做“空气受力”计算；不把`E=r鞋底`当物理定律，也不认定未接触面积必然严格按比例分走力。
- A集中范围、两条映射曲线、极小接触衰减速度仍待填。需验证极小接触时A不无限放大、E趋弱，使擦到一点不是稳定断裂技巧；同点换鞋的差异应来自真实几何，而非额外鞋种倍率。
- **零交集确认为踩空，不参与载荷计算。** 踩空后跳过踩踏时机轮，车辆继续前进并冲出测试道路撞上防撞墙，显示“未完成制动”，消耗一次测试机会；完整出口以第22章为准。

### 21.3 F：实际力度、疲劳与暴躁

- 实际踩踏力度F范围为**80～1612 N**，超出上限截为1612 N。通常在1600 N以内是分布调校目标，不在锁定后随机压回；避免曲线大段都被截成上限。
- 计算路径：`意图力度 → 人体疲劳力量衰减 → F（80～1612 N截断）`。接触损失在A有效中处理，不能把踩空损失覆写为“玩家没有踩那么重”。档案区分意图力度、实际F、接触效率与最终T。
- 人的疲劳与暴躁是独立状态。疲劳**减弱力量并影响相对从容时机的中心漂移**，不增强力量、不抬高最低段、不收窄或放宽内部低力度时机区间、不延迟停止采样。确认按下仍立即锁定。
- 暴躁压缩内部低力度时机占比、扩大高力度时机占比，不只是改变每步增加多少N；同时可影响抖动/变速和角色预备动作，具体强度待定，不作为最终K重复放大。
- 两种状态可以竞争：暴躁更想猛踩，疲劳又减力，实际F不保证逐轮增加。
- 疲劳来源可包括测试/用力历史、持续时间和温度不适；暴躁可受温度不适/此前结果影响。来源、初始值、权重、累积和恢复规则待填；没有舆论回流第一幕的循环。

### 21.4 内部时机映射：低力度区间、漂移与连续曲线

- 玩家界面使用第22章定义的**踩踏时机条**。条面保持标准长方形，但不绘制固定力度渐变、甜蜜区、安全区或危险区；本节参数只用于内部把锁定时机映射为意图力度。
- 内部相对从容时机的中心基准为`0.50`，最大漂移`±0.18`，即整条的**±18个百分点**，中心范围`0.32～0.68`；不是50%的相对±18%。
- 内部低力度时机区间按**全宽**定义为`0.10～0.04`（10%～4%）；若实现用半宽，则为`0.05～0.02`。仅暴躁收窄，疲劳不改变宽度。
- 疲劳与暴躁共同决定本轮中心漂移幅度，种子决定方向；合成权重待填，总漂移不超过±0.18。每轮开始确定中心，本轮固定，不让目标位置追逐游标。
- 从内部低力度区间向左右两端的意图力度**连续上升**，两端为当前状态的较高力度；离开中心少量距离不能直接跳到最大值，也不能在锁定后随机改写结果。
- 4%只是最低力度映射区间，不是安全区或成功区。应结合游标速度和角色动作验证可操作性，未落入该区间仍可获得适中力度并完成正常制动。
- 不设置“完美刹车”综合评价。唯一主成绩是第22章定义的`100–0制动用时`，低力度不等于更好成绩，也不保证结构安全。

### 21.5 最终K仅姿势，旧因素的去向

### 21.6 一个平滑温度、可逆余量变化与永久损伤

- 一个游戏温度θ代表简化共同热环境，不维护两份独立舱内/部件温度。天气决定初始温度与环境目标，空调改变目标，当前温度平滑趋近，不点击即瞬变。
- 舒适区外的冷热不适主要影响人体疲劳/暴躁的累积速度。空调缓解后续负担，不瞬间清空既有疲劳/情绪。
- 部件采用`M有效=M剩余×C温度(θ)`。C温度为有限正值，常见范围影响较小、游戏极端范围影响较明显；舒适/极端区、曲线方向/幅度、平滑时间常数待填。不默认低温必脆断或高温必更结实，不伪装真实材料规律。
- 温度造成的即时承受能力变化可恢复，永久测试损伤不可逆；空调不是修复按钮。
- **先判本轮，再记次轮损伤**：用当前T和本轮开始的M有效计算q，判未断裂/断裂；未断裂时再按本轮实际载荷记录新增永久损伤，影响下一轮M剩余，不反过来降低本轮阈值而自放大。
- 普通载荷损伤为零或很小，接近边界才明显增加，后续可能更易断；不每次固定扣寿命、不加额外断裂骰子或三次保底，不模拟复杂长期材料寿命。
- M0、损伤起点/增长曲线、断裂边界、换车余量和温度初始化仍待填。“一般不容易断”通过正常输入很少进入损伤/断裂区来调校。

## 22. 方案 A：标准化 100–0 km/h 制动测试（对比方案）

### 22.0 方案目标与优先级

本章将第一幕的前台目标明确为：**验证车辆的 100–0 km/h 紧急制动能力，并在最多三次标准化测试中取得更短且可复现的制动成绩。** 玩家不是为了踩断踏板而操作；断裂是在正常追求制动成绩时暴露的结构异常。

本章覆盖旧章节中与刹车点、松手时机、甜蜜区价值、感觉用时、实际用时、结算字段和继续测试动机冲突的内容。原有落点、接触、力度、人体状态、温度、永久损伤、发帖和舆论结构继续保留。

### 22.1 玩家前台目标

- 每次测试统一从 100 km/h 开始，目标是缩短车辆从 100 km/h 降到 0 的制动用时。
- 唯一主要挑战成绩为`100–0制动用时`；`制动距离`由同一次车辆模拟产生，仅作为辅助事实数据，不参与最佳成绩判定或综合评分。
- 车辆达到有效制动上限后，额外踏板力几乎不再改善成绩，但仍会提高结构载荷与隐藏损伤风险。
- 不设置"停入目标区"、S/A/B/C总评分或"踩断即成功"。玩家明面上只是在完成一次标准制动测试，踏板断裂属于隐藏事件。

### 22.2 单次测试流程

```text
车辆自动发车并加速至100 km/h
→ 稳定保持100 km/h并接近固定测试线
→ 制动信号亮起
→ 玩家点击响应，单独记录反应时间
→ 立即进入子弹时间
→ 落点并计算真实接触
├─ 零交集：判定踩空，跳过踩踏时机轮
└─ 有交集：进入踩踏时机轮，锁定实际力度
→ 子弹时间结束，同一瞬间开始车辆与结构计算
├─ 正常建立制动力：车辆降至0，完成测试
├─ 踏板断裂：主动制动力归零，车辆仅受自然阻力
└─ 踩空：未建立主动制动力，车辆继续前进
→ 未能在测试道路内停车时冲出终点并撞上防撞墙
→ 显示本轮完成成绩或"未完成制动"
```

- 固定测试线用于统一每轮初始条件，玩家不自由选择道路上的刹车点。
- 玩家必须亲手响应制动信号，以建立"这一脚由我发起"的操作归属。
- 子弹时间是一次踩踏瞬间的展开表达。玩家在界面中停留的墙钟时间不计入车辆运动、制动用时或制动距离。
- 取消旧版松手时机玩法；正常测试为"落点含接触→踩踏时机"两轮，踩空则在落点判定后直接进入失败分支。
- 踩空与踏板断裂都属于未完成制动，均消耗一次测试机会。若踏板断裂后仍有剩余机会，继续测试的行动必须表现为"换车再测"。
- 道路终点使用测试防撞墙或吸能墙，不使用断崖、裂谷等高致命性场景。

### 22.3 方案 A：反应时间与车辆成绩分离

- `反应时间`从制动信号出现计至玩家点击，仅作为测试详情。
- `100–0制动用时`从子弹时间结束、制动开始建立计至车速为0。
- `制动距离`从同一时刻开始累计，直到车速为0。
- 反应时间不计入主成绩，不改变100–0制动用时与制动距离，避免玩法退化为抢按或背节奏。
- 本方案不以"危险出现后的总停车时间/总停车距离"评价玩家；如未来展示，只能作为辅助数据，不能替代车辆主成绩。

### 22.4 同一输入的双通道

```text
玩家操作
├─ F × E传导 → 有效制动输入 → 制动力建立 → 速度变化 → 制动用时与距离
└─ F × L × A有效 × K姿势 → T结构 → q=T结构/M有效 → 未断裂 / 断裂
```

车辆通道新增：

```text
F制动 = F × E传导
目标减速度 = BrakeCurve(F制动)
```

- `BrakeCurve`为单调增加后逐渐饱和的有界曲线，不能使用简单的`常数/F`。
- 接触充分时力量传导较好；擦边或接触不足时，制动力上限或建立速度降低。
- 结构通道继续使用第21章的`A有效=A集中×E传导`，不得因车辆通道使用E传导而在结构结果中重复乘E。
- 小面积充分接触可以同时具有较高制动传导与较高结构风险；只擦到一角则可能制动较差但局部风险不低。
- 局内结构结果仅区分**未断裂**与**断裂**。本轮未断裂仍可累计隐藏损伤，影响后续轮次，但不形成可见的变形状态、数值或结算字段。
- 一旦断裂，主动制动力立即归零；车辆只受空气阻力和滚动阻力影响，测试道路范围内无法停下。

### 22.5 最小车辆模拟

从`v0=100 km/h`开始按固定时间步更新：

```text
当前制动力逐渐趋近目标制动力
当前减速度 = 有界制动模型(当前制动力)
当前速度 = max(0, 当前速度 - 当前减速度 × dt)
制动距离 += 更新期间的平均速度 × dt
```

模拟至少输出：反应时间、100–0制动用时、制动距离、峰值或平均减速度、实际F，以及供局外档案使用的隐藏结构结果。局内不显示踏板状态、变形状态、T、q或任何耐久数值。最大减速度、制动力建立速度、饱和阈值与自然阻力参数均为待调参数，不宣称还原真实车型。

### 22.6 踩踏时机条与腿部视觉反馈

- 原“力度条”在玩家界面中改为**踩踏时机条**。它表达角色从收到信号到完成踩踏的相对时机，不直接标注轻、重、安全、危险或固定最佳区域。
- 条面不绘制“两端高、中间低”的固定力度渐变，不绘制固定色块、甜蜜区、危险区或安全区。这样不会把会漂移的从容时机误读成恒定目标。
- 时机条的语义从左到右为：**过早反应 → 相对从容时机 → 延迟补救**。相对从容时机的位置由当前人体状态决定，可随疲劳、暴躁等隐藏状态漂移；本轮锁定后不追逐游标。
- 左端附近表示信号刚出现就受惊并抢先踩踏：角色腿部突然抬高、动作僵硬、落脚冲击明显，最终实际力度趋高。
- 中部附近表示有准备地完成踩踏：角色腿部预备动作稳定，脚掌小幅、平顺地压下，最终实际力度较低或适中。
- 右端附近表示错过时机后的补救：角色先迟疑或错过预备点，再急促提腿猛踩，伴随抖动、身体前倾或短促镜头冲击，最终实际力度趋高。
- 腿部动作表达最终实际力度F，而不只表达游标坐标：小力度为脚掌小幅移动并平稳压踏；大力度为大幅度提腿后踩踏。接触不足还应通过脚掌擦边、滑过或踩空动作表现，不能只用数值提示。
- 疲劳、暴躁、接触效率和姿势会改变最终F，因此相同的条上位置不保证完全相同的动画幅度或制动结果。动作、车辆减速和后续结果必须采用同一次锁定值。
- 玩家通过“时机条位置—角色预备/踩踏动作—车辆表现”的连续反馈学习机制；不直接在条面上告诉玩家综合好坏，不把低力度区包装成成功保证。
- 时机条只服务操作反馈，不计入100–0制动用时；子弹时间中的停留墙钟时间也不计入车辆模拟。

### 22.7 三次测试与决策动机

- 第一次用于摸底：车辆实际能做到什么成绩。
- 第二次用于挑战：熟悉操作后能否缩短成绩或复现异常。
- 第三次用于验证：较好成绩是否稳定、连续测试后是否衰减、异常是否重复出现。
- 第一次后仍可提交当前结果，第三次后必须提交；按钮语义优先使用"追加测试/提交结果"，进入第二幕后再明确为发帖。
- 继续测试的直接动力是刷新或复现成绩，不是追求更炸裂的数据。异常发生后，玩家可在立即报告与继续验证之间选择。

### 22.8 局内结算与局外档案

正常完成制动时，局内显示：

```text
第N次测试
100–0用时      2.91 s
制动距离       40.4 m
反应时间       0.34 s
实际踏板力     1326 N
```

未能在测试道路内停车时，局内显示：

```text
第N次测试
未完成制动
中止原因       未建立制动力 / 制动过程中断
反应时间       0.34 s
实际踏板力     — / 1326 N
```

- `100–0用时`是正常完成测试时唯一的主成绩；`制动距离`为辅助事实数据，反应时间与实际踏板力作为详情。
- 踩空使用“未建立制动力”，踏板断裂使用“制动过程中断”。若断裂动作已在画面中明确发生，可在现场记录中写明可见的“踏板断裂”，但不设置“踏板状态”栏，也不解释隐藏原因、阈值或耐久。
- 失败测试不伪造100–0用时或制动距离成绩；可在现场演出中表现冲出测试道路并撞上防撞墙。
- 取消旧版“感觉用时 vs 实际用时”作为核心结算对照；时机锁定到结算出现的墙钟等待只服务演出，不作为测试成绩。
- 局内不显示T、q、M有效、未断裂/断裂状态字段、隐藏状态百分比、种子或完整因果。
- 局外测试档案保留意图力度、实际F、E传导、L、A集中、A有效、T、M有效、温度、损伤、隐藏结构结果、制动力建立过程和因果来源，用于事后追溯。

### 22.9 叙事作用

第一幕让玩家真心相信自己在完成正规的百公里制动测试。第三幕可将"按测试要求尽快建立有效制动力"截断并改写成"测试员施加异常力量"或"故意暴力测试"。玩家亲自经历过统一起点、制动信号和成绩追求，因此知道自己的操作属于测试要求；上下文在传播中丢失时，表达权被夺走的冲突才成立。

### 22.10 待调参数

仍需通过手感测试确定：

- `BrakeCurve`形状、有效力度饱和阈值、最大减速度、制动力建立时间。
- 接触不足对制动力建立速度与上限的影响，以及擦边、滑过、踩空的动画阈值。
- 踩踏时机条的游标速度、相对从容时机漂移表现和锁定反馈；不得恢复固定甜蜜区或静态轻重色带。
- 腿部预备、轻踩、重踩、慌乱补救和踩空动作的幅度、节奏、抖动与镜头冲击；动画必须由最终F和接触结果驱动。
- 踩空后继续加速、测试道路终点距离、防撞墙/吸能墙位置、撞墙演出和“未完成制动”结算时机。
- 断裂发生时刻、主动制动力归零后的自然阻力参数、冲出道路的演出节奏；不得实现为主动制动力渐进衰减。
- 正常成绩显示精度、失败结果的字段、三次测试的合理差异范围，以及换车再测的状态衔接。

删除“变形迟滞”作为实现参数。局内不显示踏板状态，以上参数只能用于游戏内部匿名模型，不映射或影射特定真实车型的实测结论。

### 22.11 保留扩展：终点事故布景

此项仅作为设计储备，**当前不进入核心方案、不纳入开发范围**。待三幕流程、制动模型、结算与发帖传播设计全部完成后，再评估是否制作。

- 可考虑标准测试场、锥桶区、泡沫缓冲区、轮胎堆、维修棚或宣传背板等终点布景，用肉眼可见的后果帮助玩家理解制动距离差异。
- 所有布景必须保持相同初速度、道路长度、摩擦条件、制动公式和成绩标尺；不得因场景改变车辆物理、踏板风险或成绩可比性。
- 普通成绩偏慢只产生越线、撞倒锥桶等轻微反馈；明显事故主要对应接触严重不足、制动异常或踏板断裂。
- 布景可在未来影响事故演出、发帖词条和传播素材，但不得成为独立胜负条件或取代100–0制动成绩。
- 暂不采用断崖、裂谷、行人、对向车流等高致命性场景，避免玩家目标从测试成绩转为生存避险，也避免压过踏板断裂与舆论主题。
- 若最终制作，第一局仍固定使用可信的标准测试场；其他布景仅作为后续变化或解锁内容。

最终是否实现、实现数量及出现方式，统一留到全部设计定稿后决定。
