### 本次作者确认

- 第一版同时面向 **PC 与移动端**，两端都进入验收范围。
- **正式数值参数由作者提供**，不由 AI 擅自补全。
- 结算展示 **本次踩踏力度**，另行展示 **感觉用时 / 实际用时**；三者各有含义。隐藏因素与扭矩不公开。

### 实施约束

- 单机、全程 2D 卡通恶搞、第一人称体验，单局三幕闭环，目标约 10 分钟，不靠强制等待凑时长。
- 每次测试只有两轮：落点（同时产生接触面）→ 力度；均为一次确认按停。第三轮只保留扩展边界，不实现压力条或长按松手。
- `T = F × L × A有效 × K姿势`；`A有效=A集中(r踏板)×E传导(r鞋底)` 已确认。保留乘法耦合，T 为游戏等效破坏载荷，不宣称为严格物理扭矩。疲劳与暴躁进入 F，温度进入人体状态与部件承受余量，不重复作为最终 K 倍率。
- 暴躁与人的疲劳是独立变量：暴躁压缩低力度位置占比、扩大高力度位置占比，并收窄甜蜜区；人的疲劳减弱可用力量，并影响甜蜜区中心漂移，不抬高最低力度、不放宽或收窄甜蜜区，也不延迟按停。游标抖动/变速的具体强度待调。
- L 统一以真实交集的面积重心和杆端支点计算；鞋中心另存为操作落点。踏板覆盖比例负责载荷集中，鞋底接触比例负责传导效率，区分“小鞋底充分踩中”和“大鞋底大部分踩空”；联合结构 A有效=A集中×E传导 已确认，范围/曲线仍待填，零接触不进入载荷计算。
- 力度 F 范围为 80～1612 N，超过 1612 N 截断；一般结果在 1600 N 内是分布调校目标，不锁定后伪造结果。甜蜜区中心基准 50%，最大漂移 ±18 个百分点；全宽 10%～4%，仅暴躁收窄。甜蜜区到两端连续渐变，两端为本状态的最高力度，不做陡跳或断裂奖励区。
- 一个游戏温度平滑趋向天气/空调决定的目标，同时影响人体状态累积和部件有效承受余量；测试永久损伤另存，降温不等于修复。完整确认口径和未决边界见第 4.1 节。
- 标准长方形力度条，数值两端大、中间小；隐藏状态不变成百分比、心率图或额外状态图。
- 总测试次数最多 3 次。依最新第 16 章，断裂后可换下一台继续，仍消耗同一个总次数上限；第三次结束必须进入发帖。首次测试后可提前发帖。
- 换车只是叙事动作，不做预算管理；断裂是多因素耦合的意外，不做保证断裂或固定中奖概率。
- 第一幕必须真的好笑；清算冷静、洪流嘈杂，之后笑声变味。
- 清算 → 原帖出现 → 曲解扩散 → 多帖聚焦；最终帖署名是玩家自己，内容不是玩家原话，优先遵循“崇高化”落点。无系统总结，无局内重新开始按钮。
- 不做独立传播树，不恢复局内传播数字栏。来源关系保留为内部数据，供点击追溯。
- 详细因素在局外测试档案查询；清算只说因果，不罗列因素数值。结算力度与时间对比为已确认的展示内容。
- 隐藏交互先不加提示；是否加轻提示由后续测试反馈决定，不自动启用第二局高亮。
- 感觉用时按力度锁定至结算出现的真实墙钟时间记录，显示上限 4.0 秒；同时保存未截断原始值。实际用时来自刹车模拟，不固定为示例 0.8 秒。
- 保留 0.5 秒完全静音与最终结局安静；金属极限事件音整局不重复滥用。

## 2. 技术路线与范围

- 沿用 2D 脚手架，游戏代码全部放在 `scripts/`，素材放在 `assets/`。
- 采用新 UI 组件系统，使用 `UI.Scale.DEFAULT` 与安全区。16:9 是演出画幅，不强制所有屏幕都是 16:9；不同宽高比需处理留边与交互区域。
- PC 的确认键、方向键、鼠标与移动端点击统一映射为游戏动作；防止一次输入跨阶段触发两次判定，防止键盘长按重复提交。
- 纯规则、UI、演出分离。数值、词条条件、节奏与内容配置独立于页面代码；游戏逻辑不依赖网络、视频或 AI 服务。
- 建议首版采用离线模板内容，后期可批量生成候选文案并人工筛选入库；不把在线 AI 推理作为游玩依赖。清算、定性、传播档位及结局选择始终由规则与真实记录决定。
- 从 D1 起记录随机种子、配置版本、输入时间与关键结果；视觉随机与规则随机分离，保证动画或帧率变化不随意改写结局。
- 档案使用平台允许的存储方案。必须核验 PC 与移动端实际发行运行环境的跨启动持久化；当前预览可运行不等于存档可永久保留，不承诺浏览器 File 存档刷新后仍存在。
- 视频 V1/V2/V3 仅作为可替换演出插槽，无素材、不支持、加载失败时使用 2D 动画完成相同剧情出口。此计划不授权生成视频；需要时单独由作者明确提出。

### 渐进式模块结构

按阶段建立需要的模块，不预先创建大量空文件：

```text
scripts/
  main.lua                 引擎入口、初始化和清理
  core/                    会话流程、输入动作、随机与记录
  config/                  数值配置、词条条件、内容模板
  gameplay/                测试规则、结算、发帖、传播规则
  ui/                      各幕界面、档案、公共控件
  presentation/            2D 演出、音频、可选视频插槽
  storage/                 档案保存、读取、校验与版本处理
  tests/                   规则和流程验证入口（开发用途）
assets/
  image/                   场景、角色、鞋子、头像
  audio/                   音效与环境声
  video/                   仅在有已确认素材时使用
```

实际文件按职责逐步拆分，不把全部系统塞进入口；开发验证入口不暴露为正式游玩菜单。

## 4. 正式参数与确认记录

### 4.1 2026-10-14：已确认的新设计口径（优先于旧策划与旧 Demo）

本节持久记录作者在 P1.3 后的数轮设计确认；是后续执行依据，不表示代码已经实现。2026-10-14 作者已确认面积联合结构，并授权同步策划案、开工清单、项目 README 和本计划后提交/推送这些文档。原策划保留历史章节，以新增第 21 章覆盖旧口径；第 7 节旧工作记录不覆盖本节。

#### A. L：杆端支点与真实受力位置

- 确认为刹车杆连接踏板面的正面示意图，支点在杆的一端，不是杆与踏板面的连接点。
- 支点、杆、踏板面使用同一份归一化场景几何；再统一映射到界面，改变窗口尺寸或 DPR 不能改变 L。此图是游戏受力示意，不是从正面投影反推出精确三维扭矩。
- 所有有效接触统一用鞋底与踏板真实交集的面积重心作为受力位置，不在鞋中心跨出边界时突然换算法。鞋中心保留为玩家操作落点，与受力位置分开记录。
- 多块交集按面积加权：`受力重心 = Σ(交集块面积 × 块中心) / 总交集面积`；不把分段鞋底的缺口或包围盒算进来。
- 零接触没有受力重心，不除以零，也不进入 L/A/T 载荷计算。
- L 的范围、参考力臂尺度与映射曲线尚未给值，不直接用显示像素距离替代。

#### B. 面积：载荷集中与接触传导的联合映射（结构已确认，参数待填）

- 保留“小接触面导致局部压强集中”的方向，A 用有限数值范围表示游戏载荷集中系数，不是以帕斯卡为单位的实测压强，不直接使用无上限 `1/r`。
- 作者指出两种小面积情形不能等同：高跟鞋等小鞋底充分踩中踏板，可以载荷集中；大鞋底只有一角踩中、大部分在外面踩空时，需要体现有效施力变弱，不能把所有擦边都当成最高危险输入。
- 至少保留两种独立几何比例：
  - `r踏板 = 交集面积 / 踏板面积`：载荷集中映射的输入。
  - `r鞋底 = 交集面积 / 当前鞋底总面积`：区分充分接触与部分踩空的输入。
  - `未接触鞋底面积 = 鞋底总面积 − 交集面积`；`未接触比例 = 1 − r鞋底`。用比例即可表达，不另做逐块“空气受力”计算。鞋底总面积只包含真实鞋块，不包含鞋底缺口。
- **2026-10-14 作者已确认联合结构**：`A有效 = A集中(r踏板) × E传导(r鞋底)`，A有效作为载荷公式中的 A。A集中随覆盖降低表达载荷集中且有有限上限；E传导为有界接触效率（零到一），充分接触接近一、接触减少时降低。E 不是新的随机隐藏 K，不能再把同一传导损失另乘一次。具体上下限、映射曲线与极小接触衰减速度仍待作者给值，不再重复询问是否采用联合结构。
- 没有依据认为所有未接触面积都严格按比例“分走力量”，不直接把 `E=r鞋底` 当物理定律。姿势/施力重心与鞋形会影响实际力分配，这里只建立一致的游戏简化。
- A 与 E 的联合趋势应验证：充分踩中的小鞋底可有集中效果；同一鞋底移出踏板时不能出现 `E→0` 而 A无限放大；同一落点换鞋结果必须来自真实几何而非额外鞋种倍率。
- `交集面积=0` 已确认是踩空、不参与计算；踩空消耗机会与是否跳过第二轮/如何演出的具体流程尚未定案，不擅自规定可免费重试。

#### C. F、疲劳与暴躁

- 实际踩踏力度 `F` 在 80～1612 N；超出上限截断为 1612 N。通常在 1600 N 内是正常分布的调校目标，不在锁定后随机压回数值。
- 第二轮标准长方形，甜蜜区到左右两端连续渐变；两端为本状态下最高力度。暴躁压缩低力度的空间占比、扩大高力度占比，不仅仅改变每次增加多少牛顿。
- 人的疲劳是身体/动作控制状态，与部件测试损伤不同。疲劳减弱可用力量，不增强力度、不使最低段整体上移，也不通过输入停止延迟制造“按了还在走”。按下立即采样原则保留。
- 疲劳与暴躁独立记录：暴躁改变选值曲线和选值过程，疲劳减力；两者可以竞争，不必每测一轮实际力度都更高。
- 已支持的计算结构为 `意图力度 → 疲劳力量衰减 → F（80～1612 N 截断）`；疲劳衰减系数和曲线尚未给值。
- 接触损失在已确认的 A联合结构中处理，具体参数待填，不把“部分踩空导致的有效载荷损失”覆写成玩家没踩那么重。档案应能区分意图力度、实际 F、接触效率和最终载荷。
- 疲劳来源可包括测试/用力历史、时间与温度不适，暴躁可受温度不适和此前结果影响；具体来源、权重、恢复和累积速度待作者定值。没有舆论回流影响第一幕的循环。

#### D. 甜蜜区、渐变与漂移

- 甜蜜区不是“断裂最佳区”或奖励区，而是最低力度/从容控制的理想区；命中不保证断裂或成功，区外也不自动失败。若后续要定义“完美刹车表现”，须结合刹车模拟和实际需求单独定目标，不能默认 80 N 就保证完美停车。
- 中心基准为 `0.50`；最大漂移为 `±0.18`，即全条的 ±18 个百分点，中心范围 `0.32～0.68`，不是 50% 的相对 ±18%。
- 区间按**全宽**定义，范围 `0.10～0.04`（整条 10%～4%）；若代码使用半宽则分别为 `0.05～0.02`，不得把旧 Demo 的 halfWidth=0.10 当成全宽 10%。
- 仅暴躁增加时区间变窄，人的疲劳不收窄、也不放宽区间。宽度映射与暴躁强度关系尚未定值。
- 疲劳与暴躁都参与中心漂移：疲劳体现难以准确控制力度，暴躁体现动作不稳定。二者决定本轮漂移幅度，种子决定方向；合成规则与各自权重待定，总幅度不超过 ±18 个百分点。
- 漂移按每轮开始确定，本轮不让甜蜜区不停追逐；区间外向两端平滑上升，不因离开 4% 区间一点就直接跳到最大值。
- 4% 是最低段宽度，不是全部安全区宽度。命中窗口与当地游标速度一起测试，没命中甜蜜区仍可得到适中力度；不把窄区间误判成强制高精度通关门槛。

| 旧项 | 最新处理 | 作用位置 |

| k1 加载速率 | 删除 | 不再作为停手间隔倍率 |
| k2 方向/抖动 | 删除 | 不增设方向随机倍率；系统游标抖动只影响玩家选到的 F，不重复放大结果 |

姿势 ────────────────────────────→ K姿势

T = F × L × A有效 × K姿势    （联合结构已确认，正式映射参数待填）

#### F. 一个温度、人体累积与部件损伤

- 只用一个游戏温度，代表简化的共同热环境；不维护独立舱内温度和金属温度。天气决定初始/环境目标，空调改变目标，当前温度平滑趋近，不点击即瞬变。
- 人体以舒适温度区间为基准。偏热/偏冷的不适主要改变疲劳、暴躁的累积速度；空调缓解后续负担，不瞬间清零已经积累的疲劳或情绪。
- `M有效 = M剩余 × C温度(θ)`：温度系数有限且为正，常见温度内影响较小，游戏设定的极端温度内影响较明显。舒适区、极端区、温度曲线方向/幅度与变化时间常数尚未给值，不默认低温必断或高温必更结实。
- 温度造成的即时承受能力变化可随温度恢复；测试永久损伤不可逆，调整空调不能修复杆或踏板。
- 永久损伤取决于每轮实际载荷与当时余量，而不是每次测试固定扣寿命。使用本轮开始的 `M有效` 计算载荷比 `q=T/M有效`，先判本轮结果，再记录未断情况下的新增损伤，避免同一轮新损伤又回头降低阈值、重复自放大。
- 普通载荷区永久损伤为零或很小；接近边界时损伤明显，后续更易断；超过断裂边界则本轮断裂。具体损伤起点、增长曲线、变形/断裂边界、初始余量待给值。
- “一般不容易断”靠正常输入很少进入损伤/断裂区域调校，不加每轮固定扣血、额外随机断裂骰子或三次保底。三次机会规则不变，损伤不增加新的操作轮。
